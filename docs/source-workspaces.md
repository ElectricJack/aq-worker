# Local source workspace adapter (WRK-06)

This page records the WRK-06 baseline. The opt-in worker 0.3.3 transfer consumer,
cold downloads and journal format 4 are described in
[resumable source handoff](source-transfers.md).

The supported adapter is `source::GitClient`, talking only to aq-git's public Unix socket protocol 1. `GitService::start(executable, binary_sha256, state_root)` explicitly starts an operator-selected pinned executable, validates its hash and permissions, uses a private root and unique private socket, and verifies advertised artifact/profile/operation capabilities. `GitClient::new(socket, root)` connects to an already managed service. These runtime paths are never assignment fields or agent grants. Startup refusal and uncertain stop leave aq-git's ownership fence intact; no automatic fence clearing is attempted. One exception, in the worker service only (`aq-node-service` `AqGit::start`, swarm phase 1 ruling): when a slot's aq-git was killed (a crash, `systemctl kill`) its state keeps an active `incarnation.json`, and the next start would refuse it with `recovery_blocked`. The service then clears that fence with `aq-git recovery clear-fence` (`old_environment_stopped: true`, the evidence `{owner_lock: free, guard_pid, boot_id}`), and removes the killed aq-git's socket, only when no process holds the state's `owner.lock`: aq-git's guard and its engine hold that flock until they exit, and the kernel releases a flock its holder held when it dies, so a free lock proves the previous owner is gone. A held lock, or a socket that still accepts connections, leaves both in place and the slot retries. `GitService` itself never clears a fence.

`Runtime::reserve_source(offer, client)` applies ordinary shared capacity/pending-storage admission after validating the existing local worker binding against the frozen source UUID, identity and generation. Register local bindings using aq-git's public administration interface before admission; no worker remote credentials are accepted. Eligibility does not allocate a checkout. `import_base` imports a completed controller-staged base artifact under the private incoming area; it validates manifest identity, base and canonical digest plus current active retained receipt. The controller must durably publish the entire incoming artifact before calling it. Artifact transfer/download, authentication, and provisioned client credentials are separate consumers and are not implemented here.

`prepare_source` records preparation and a durable operation UUID before requesting a private exact-base workspace. A lost or malformed socket reply holds the reservation; reopening the journal and calling the same API replays exactly the stored request/UUID. Successful workspace paths must canonicalize inside the configured aq-git workspaces root. The synthetic fixture guardian starts its process in that workspace. The cooperative Linux subreaper guardian remains the supported writer profile; reattachment and hostile isolation are not claimed.

`bind_source_transfer` freezes the intended authenticated HTTP transfer UUID separately from the aq-git artifact UUID and validates the exact transport manifest bytes before any receipt is accepted. A central receipt must match that transport UUID, aq-git retention handle, frozen source and canonical manifest digest; those two UUIDs may differ.

`checkpoint_source` requires the guardian's stopped state and kernel `ECHILD` proof. `export_source` records the exact manifest/bundle pending bytes, attaches the artifact to a new immutable report superseding its predecessor, and preserves the workspace. Source-backed reports do not claim success until `acknowledge_source` verifies the central transfer/source/canonical-manifest receipt and adds that receipt to a new report revision. Report acknowledgement cannot release source storage before central retention. `retire_source` requires stopped writers, central receipt and explicit report retention release before asking aq-git to retire the clean checkpoint. Ordinary `retire` refuses to remove source state until that step succeeds.

`reclaim_source(attempt, expected_storage_generation, client)` refuses while any source owner in the repository is active or unacknowledged. It releases only the selected attempt's known transfer/checkpoint/base handles, then asks aq-git for conditional reconstructible cache eviction. aq-git separately rejects other unknown dependents. No cache operation deletes arbitrary folders, scans the fleet or treats upload completion as retention. Remaining pending results continue to count against node admission even after execution slots are released. Source operation history is bounded at 64 actions per attempt and the existing journal byte bound remains effective. Unknown local aq-git dispositions continue to hold execution resources as well as storage. A never-started source with no create intent can retire after explicit decline/result release without inventing a guardian proof. A pending or allocated create cannot use this shortcut.

The default configured storage profile permits at most 64 MiB bundles and 512 MiB expanded source data. Install the public administrator configuration described by aq-git `docs/operations.md` before provisioning/importing bases into the dedicated fresh root: `artifact_limits.json` with `max_bundle_bytes:67108864`, `max_expanded_bytes:536870912` and an operator-selected `disk_reserve_bytes`. The runtime verifies advertised capabilities against `--source-max-bundle-bytes` and `--source-max-expanded-bytes` (defaults above), refusing the large engine defaults until explicitly configured. Existing roots must already have operated under that profile; lowering a configuration file does not shrink existing data. Normal builds never read repository-private metadata.

This profile reserves one 512 MiB repository pool allowance per repository, plus at least 577 MiB declared workspace/artifact headroom per active source attempt; the fixture uses 1 GiB per attempt. Two projects sharing one repository pay its pool allowance once. The configured synthetic driver supplies an 8 GiB managed disk admission budget and 256 MiB pending artifact budget. Pending input/output staging is measured at local import/export boundaries, incoming files are removed only after current source retention is verified, and actual over-budget bytes remain protected while new admissions fail. Retired cache and unreclaimed artifacts remain charged until successful eviction/staging removal. Actual stopped workspace sizes are observed in a bounded traversal (100,000 entries, depth 64, no symlink following); unknown accounting places the node in persistent drain. Physical headroom is rechecked on the aq-git volume, even when the journal uses another volume. These are conservative admission/observation bounds with sampled aq-git enforcement, not hard OS quotas or a scale qualification.

After eviction, replaying an old transfer is historical evidence, even under a new import operation UUID. Deliberate rehydration requires a fresh central artifact export/transfer UUID and complete bundle under the unchanged authorized source binding. `import_base` rejects historical released receipts rather than claiming the cache is warm. This was verified against the pinned component using public calls only.

Configure the outbound synthetic driver with `run-execution --aq-git-binary /absolute/aq-git --aq-git-sha256 <binary-sha256> --aq-git-state-dir /absolute/private-root`, optionally `--git-executable /absolute/git`. The three aq-git flags are required together. After verifying the managed service, the driver advertises `source-workspaces-v1`; it admits only exact registered bindings whose frozen base is already available. Cold base downloads remain WRK-07. It prepares before guardian launch, checkpoints/exports after stopped proof, emits `source_pending`, and preserves the workspace/artifact/report without submitting completion. Recovery likewise withholds source reports without a central receipt. Without this configuration the default driver advertises neither source capability and refuses source-bound offers. No driver advertises `source-transfer-v1`. WRK-07 adds the resumable HTTP consumer and WRK-08 adds a production harness. This document does not claim those clients already exist.

## Verification

Ordinary `cargo test --workspace --all-features` uses deterministic public socket peers and needs no sibling checkout or service. The real fixture is explicit:

```sh
AQ_GIT_TEST_BINARY=/absolute/pinned/aq-git cargo test -p aq-worker --test source -- --ignored --nocapture
```

It creates unique disposable Git repositories and central/worker roots, uses real aq-git public operations, imports an exact base, runs the synthetic guardian in an independent workspace, checkpoints dirty source, exports and validates a central receipt association, retires only after release, evicts the cache, rejects an old released transfer, rehydrates a fresh transfer for another project, and verifies unsupported `.gitattributes` refusal and active-owner eviction protection. The same real fixture runs the actual `aq-worker run-execution` binary against a fake authenticated HTTP coordinator and its configured real aq-git service, verifies source capability negotiation and workspace preparation/collection, and proves no completion/report acknowledgement occurs before central retention. Normal tests cover lost create responses with reopen/replay, preparation capacity holds, same-ID changed binding conflicts, current binding mismatch, disk admission pressure and checkpoint refusal before stopped-writer proof.

Recorded binary: source `f3660a89cbeac0e068105af2926dfdcb06a1daad`, SHA256 `9de33fd4e79d68a9cb8c72532ee03825dca3a3dbaf979bcd8770a53ef8fe9d3a`, built in pinned Rust 1.96.1 Bookworm image `sha256:a339861ae23e9abb272cea45dfafde21760d2ce6577a70f8a926153677902663`. Public source archive SHA256 is `8f6a2f8ce04361c3cabaff5de7274505e28a042235da18cc346086f47e4c6cd5`. No sibling tree or private metadata is a build dependency.

Worker implementation version is 0.3.1 and journal format is 3. Format 1/2 migrations retain old guardian evidence/reports without fabricating source ownership or transfer receipts. A retained frozen format-2 reader verifies that old workers refuse format 3 without changing the file. Protocol package remains independently versioned 0.2.0. Managed aq-git receives a Linux parent-death termination signal; its own lifecycle guard/fence decides cleanup certainty. Restart reconciliation retries pending source collection from stored operation IDs after guardian stop proof, without relaunching the agent.

Initial 0.3.0 candidate checks on 2026-10-30: 73 ordinary workspace tests passed (66 retained baseline plus seven new protocol/source/migration cases), the explicit pinned real aq-git/workspace/actual worker binary fixture passed in 2.90 seconds excluding compilation, formatting passed, and strict Clippy passed across all workspace targets/features. The ordinary suite includes the retained Linux guardian crash cases; the real fixture uses the small configured source profile. These developer results do not establish production harness, WAN transfer, filesystem hard quota or many-agent performance acceptance.

The 0.3.1 recovery fix retries the same durable stopped observation before delivering the final report. A retryable network/endpoint failure during this exchange previously exited the driver before entering its result-report retry loop. The bounded retry keeps the original observation/report identities and stopped proof, never renews execution authority, and preserves data on exhaustion or permanent credential refusal. A deterministic actual-worker HTTP fixture injects a post-stop 503, proves the old failure, then verifies identical observation replay, one report and no renewed grant/relaunch. The full 74-test suite, formatting and strict Clippy validate the corrected candidate; the prior real source-workspace fixture remains source-profile evidence, without claiming it was rerun for this narrow retry fix.
