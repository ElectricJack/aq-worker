# Opt-in native phase observed-host checkpoint

Source **40d6e36**, design **1b8cefd** (reviewed), based on durable phase execution **82496ef** and unchanged host0.1.4. Worker journal format **9**. No public admission/session/host wire, frozen archive, host core file, binary entrypoint, server migration or default runtime capability changed. The physical API is compiled only for test/test-support; that feature explicitly propagates the host's existing test-support fault hook. Production default exposes no synthetic launch API. Resource policy is the existing CallerAdmission with a fixed synthetic-only reference, not a hard memory/CPU/process ceiling claim.

The component joins actual retained PreparedPhaseInputs and an in-process DurablePhaseExecution token. An outer NativeLaunchIntent is fsynced before any per-attempt host/adapter/ELF-load hook. It binds original grant/runtime/Accepted/Prepare/manifest/session/logical reservation identities, exact local/hard caps, private root identity, synthetic installation/profile pins, terminal epoch1 and fixed report operation IDs. Host callbacks durably bind the real configuration, physical guardian and start intent. Only actual prepare_observed, VerifiedBlankBaseline, a durable release decision and current cap check can release the executable gate. Only real positive sealed-FDexec evidence can record local Running and the typed Started request. No readiness timestamp renews permission.

One bounded bootstrap/writer admission serves synchronous callbacks without recursively calling async storage or holding Owned around tmux waits. Safety stop has an independent lane and exact stop-only host recovery; the original guardian permit also expires independently. Opaque stopped proof is cloned before persistence so the physical-handle mutex is never held across fallback fsync. A canceled waiter leaves its admitted job/handles retained. Unpolled/refused admission claims can be removed only before any job/intent/effect was possible; once admitted, the attempt is one-shot. Explicit stop tombstones share the registry mutex with cleanup and cannot be reset by dropping an unadmitted future. Original input/resource/source holds remain in all cases.

The synthetic program is selected only from explicit installed configuration, never from an offer/command string. It accepts fixed context/marker/mode arguments, refuses startup payloads above4KiB, copies unchanged bytes to a private fixture marker and has no provider/node credentials or external network calls. The helper/tmux paths are trusted operator-controlled synthetic installations: rehashing detects current changes but does not prove immutable paths after a check. The harness image itself is bounded and kernel-sealed. The coordinator/issuer, provider/runtime/harness qualification and host-matrix Git peer are synthetic; HTTP, journal/fsync/private files, tmux/pane/guardian/kernel execution and stopped proof are actual. The separate Git matrix uses actual pinned Git.

Typed Started ACK is a historical fact, never execution renewal. First unsupported responses remain unacknowledged; exact lost-ACK retry preserves the original request. An acknowledged receipt can be read after stop without another network mutation. No remote phase Started acceptance is claimed: daemon phase-origin consumers require separate qualification. Pre-Running stopped facts may lack pane/root status and are not forced into the prior-Started stopped DTO. Outer intent with missing guardian identity, guardian loss, uncertain persistence or absent stopped proof remains Unknown/held. No suppression, NeverGranted, task success, source release, cleanup or blind relaunch follows. Recovery writes only actual opaque stopped facts/uncertainty and never restores invocation, resources, live grant or a new terminal.

Bounds are64 admitted registry entries/tombstones, one bootstrap and one independent stop lane, the existing journal/input byte budgets, one observer per attempt and the existing4-entry/16MiB sealed ELF pool (4MiB per image). This profile's transient startup/context copies are each at most4KiB. Output polling returns bounded local acquisition events only: reader loss/discontinuity remains explicit, no reattach, Snapshot, resize barrier/order, renderer completeness, Unicode/alternate-screen or public output-frame qualification is implied. No provider/default driver activation is included. These results describe a finite two-thread qualification profile, not saturated-start or500-agent capacity.
