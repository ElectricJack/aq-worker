## Delivered boundary

`crates/aq-worker/src/native/runner/sandbox/auth.rs` provides a dedicated `RunnerHttp` constructed from a B6b runner-private permit file and original authenticated handoff observations. It accepts no node or Cloudflare credentials. Its closed routes cover material, Prepared, Started, renewal, observations, all five terminal relay operations, artifact upload, source members, results/stopped, and mail poll/ack. Every request uses the permit bearer.

B1's pinned in-repository contracts validate phase, attempt, node boot, sandbox, channel, generation and deadlines. Explicit request bindings and nested identity fields are checked before network I/O. Preparation cannot use execution operations. Original CLOCK_BOOTTIME observations and kernel boot identity prevent file reload from restarting authority. Grant upgrade and renewal installation validate the prior permit, correlation and monotonic revision; repeated awaiting-node-readoption replies change no deadline. Server refusals revoke the shared client across all channels; unavailability grants no time.

`permit_transport.rs` adapts the client to B6a1. The runner checks the exact client/permit/authority/delivery binding before preflight or launch. The guardian observes shared authority loss even while renewal is pending, then uses the existing stop proof and preservation path. No node credential is required by that runner path. The CLI accepts `--permit-file` and `--server-url` and does not load `worker.toml` for sandbox-run.

Legacy node-only HTTP clients are unchanged. Downstream runner integrations must use `RunnerHttp` through the supplied exchange; this work does not convert node-controller operations to runner operations.

## Pending B2 contract — explicit limit

Supervisor message `msg-0730a80b65a14d709d14e053bb9142b1` confirms that B2 has not published its HTTP envelope/receipt contract, and authorizes the injected `RunnerExchange` with fixture-backed B6a1 DTOs. These are local trusted seam assumptions, **not final wire schemas**:

- Renewal returns `RenewalOutcome::{Delivered, Refused, Unavailable}`. Delivered contains `RenewalDelivery { response: B1 RunnerRenewalResponse, context: B1 PermitContext, server_now_ms: u64 }`. The context is the authenticated grant context before mutation. Request and nonce are supplied separately; original sent/received boot observations are captured by the transport.
- Retention consumes `StoppedAttempt`, including attempt identity, workspace and stopped proof. It returns `RetentionReceipts { source: Option<CentralReceipt>, result: Option<CentralReceipt> }`. Each `CentralReceipt` contains `receipt_id`, `attempt: AttemptKey { launch_id, attempt_id, manifest_digest }`, and `artifact_digest`. The exchange must durably retain actual immutable bytes before returning authenticated central receipts.
- Completion consumes `RetainedAttempt` and returns `FinishedReceipt { receipt_id, attempt: AttemptKey }`.
- Raw HTTP JSON bodies and response bytes remain caller/codec-owned. The boundary authenticates and limits scope; it does not treat a successful HTTP status as a valid mutation receipt.

There is deliberately no production `RunnerExchange` codec. `sandbox-run` validates its private handoff/permit and explicitly refuses before launch with “B2 receipt codec is unavailable”. Production server compatibility and end-to-end launch are unverified until B2 publishes the pinned contract. This limit is authorized for this task; B2 integration is supervisor-routed. No server-side enforcement, mailbox semantics, lease binding, user permissions or Access-header injection is implemented here.
