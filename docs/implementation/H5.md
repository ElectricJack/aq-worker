## Implemented path

`crates/aq-worker/src/hibernation/` implements both halves over CON-03 `aq-lifecycle-protocol` 0.1.0 types. AQ, central retention, the guardian, the node and the tmux host are ports (`LifecycleApi`, `CentralRetention`, `SuspensionPorts`, `SessionLauncher`). That way H4's route adapter and the production retention and launcher adapters plug in without changing the state machine.

**Suspension (`suspend.rs`).** A `Suspend` directive must be bound to this worker's exact binding; otherwise it is refused as stale. Its `SuspensionIntent` is journaled under `canonical_digest(intent)` (`journal.rs`, durable replace). A repeated directive recovers the same transition and returns the same `ParkingReport` and receipt. A different intent against the same journal is refused. The steps run in this order, and each is journaled before the next:

1. Request a checkpoint. A summary over `max_summary_bytes` (16384) or with a mismatched digest becomes `CheckpointClaim::Missing`. The checkpoint is journaled with a fixed message id before it is sent, so a resend has the same id and digest.
2. Close input, then stop writers through the guardian. A stop that is not `ReportedStopped` parks `Held`: no snapshot, no upload, no compute release.
3. After stop proof, capture the credential bytes into zeroizing memory and snapshot the workspace (`archive.rs`, including `.git`, dirty tracked and untracked files). Then scan every entry path and byte, plus the checkpoint bytes, for credential paths and secret substrings. A leak, a symlink, a special file or an oversized source is an explicit `Held`, never a silent drop. The scanned snapshot is written to protected disk and recorded in the journal.
4. Delete the credentials (runner `permit.json`, `provider.key` and `access.json`, plus the Claude and Codex subscription logins) and fsync their directories. This happens on `Held` too. Only sha256 fingerprints are journaled.
5. Upload Source, then Checkpoint, as resumable chunked uploads. Each artifact's operation id, offset and receipt are journaled. A receipt is accepted only if it matches the artifact digest, role, length and `canonical_digest(binding)`.
6. Reconcile the effects named by the summary's pending operation ids.
7. Release compute, then send `ParkingReport{RetainedSuspended, compute_released: true, protected_disk_released: false}` and require `ParkingRecorded`.

`release_disk` works only from `RetainedSuspended` and with an explicit directive. It removes the protected snapshot and sends a second report with `protected_disk_released`, the directive, and zero local bytes.

**Continuation (`continuation.rs`).** A wake is a fresh grant carrying a `ContinuationAttachment` whose successor must equal the grant. The attachment is journaled by digest, and on first use the sandbox workspace must be empty. Source and Checkpoint are fetched from central retention only (no node-local cache) and verified against the receipt length and digest. The checkpoint's binding and continuation generation must match the attachment.

The source is restored into a staging directory and then renamed into place. Restore refuses path escape. The bootstrap instructions (`aq-continuation/bootstrap.json`) carry the admission, generation, attachment digest, outcome, summary, pending operations and held task messages. After that the launcher starts one fresh session, which receives fresh scoped credentials.

The operations gate stays `AwaitingBootstrapAck` until AQ returns `BootstrapAcknowledgmentRecorded` for the exact ack. The ack must match the successor, admission, continuation, attachment digest and outcome. The ack and its message id are journaled before sending, so a lost receipt is retried under the same identity. A stale ack (from the predecessor, another generation or another attachment) is refused locally, never reaches AQ, and cannot open the gate.

What the tests cover (`crates/aq-worker/tests/hibernation.rs`):

- **No credentials in retained state:** all five credential files are deleted. Neither retained artifact (nor any decoded source entry, nor the local journal) contains a credential path or secret bytes. A secret copied into the workspace, or leaked into the summary, ends `Held` with no upload and no compute release.
- **Continuation in a new sandbox:** node A hibernates and its directories are dropped. Node B hydrates from central retention, and `git status --porcelain` shows the same ` M tracked.txt` and `?? untracked.txt`. The bootstrap file carries the summary and generation, and a fresh session gets fresh credentials. The gate opens only on the exact ack. A replayed attachment does not relaunch.
- **Crash at every boundary:** `SUSPENSION_BOUNDARIES` (16) and `CONTINUATION_BOUNDARIES` (5). In each case recovery ends in a valid report with writers stopped, input closed and compute released exactly once. There are exactly two retention commits, one checkpoint and one parking message id, effects run in order, and exactly one session is launched.
- An unknown stop holds without snapshot or release. Disk release requires a directive, is idempotent, and is refused on `Held`. A conflicting or stale directive is refused. A lost ack is retried under the same message id. Stale acks are refused. A missing or corrupt Source or Checkpoint refuses the wake with no hydration and no launch.

## Production adapters (clear-crest-61.5.1)

Recorded source base: `1343dee` (`origin/main`). These adapters cover only the parts that map to an existing AQ route or a local node API. No wire contract was invented.

- **`LifecycleApi` (`hibernation/http.rs`, `HttpLifecycleApi`).** It speaks to the aq-server lifecycle routes.
  - `GET /v1/worker/lifecycle/directives?attempt_id=` returns `Directives{suspend, disk_release, continuation}`. Unknown fields are denied, and each slot must hold a sealed packet of its own class.
  - `POST /v1/worker/lifecycle/packets` takes one packet and returns a receipt that must validate.
  - Auth is `Authorization: Bearer <node bearer or permit>`, sent as a sensitive header.
  - The client uses no proxy and follows no redirects. It makes one attempt per call, with a 3 s connect timeout and a 22 s total timeout.
  - Packets over `MAX_EVENT_BYTES` are refused before they are sent. Responses over 4×`MAX_EVENT_BYTES` are refused.
  - A non-2xx response becomes a `LifecycleStatus(code)` error, and the body is dropped. The journaled caller resends under the same message id, and AQ replays the original receipt.
- **`SuspensionPorts` (`hibernation/ports.rs`, `NodePorts<B, G, A>`).**
  - `stop_writers` goes through `WriterGuardian`, whose production form is `LocalGuardian` over `crate::guardian`. Stop is sent only from `Waiting` or `Running`. A guardian that is already `Stopped` is not contacted again, so a replay yields the identical observation. `StopUncertain` maps to `Unknown`, and the suspender then holds. A guardian that does not reach a terminal phase within 6 s is an error, and no stop is journaled.
  - `stopped_observation` maps the exact `Stopped` receipt (it requires `kernel_wait_echild` and `stopped_at_ms`) deterministically:
    - observation id: the first 16 bytes of sha256(receipt)
    - guardian instance: the launch id
    - writer-set digest: the digest of the guardian identity JSON
    - writer count: `reaped_count`; a count over 65536 maps to `Unknown`
    - proof: `guardian-stop:<launch_id>` over the receipt bytes
  - `release_compute` requires `ReportedStopped` and a `Confirmed` disk-preserving `PlacementBackend::stop`.
  - `release_disk` destroys under `DestroyAuthorization::operator_released(sandbox, "aq-disk-release:<id>@<version>:<digest>")` and requires `Confirmed`.
  - Backend stop and destroy confirm again on replay.
- **`SessionLauncher` shape (`hibernation/launcher.rs`, `FreshSessionLauncher<I, H>`).**
  1. It requires the bootstrap file to exist.
  2. It asks `SuccessorCredentials` for credentials scoped to the successor and refuses an empty issue. Only names in the credential layout are accepted.
  3. It plants those files, mode 0600 and durably replaced, under the runner and work roots.
  4. It calls `SessionHostStart::start(successor, workspace, bootstrap)`, which must be idempotent per successor session, because the continuation journals the launch only after it returns.

## Port-level TODOs (platform follow-up)

These four items have no AQ or harness surface yet. Each one stays behind its port, with fakes in tests, until the platform follow-up defines the contract.

1. **Central retention of arbitrary artifacts.** `CentralRetention` has no production adapter. Nothing on the recorded base retains arbitrary Source/Checkpoint artifacts under a binding-scoped receipt. After this base, `origin/main` added `artifact_client.rs` (`5127ec3`, `/v1/execution/artifacts`). The platform follow-up should adapt `CentralRetention` over that client.
2. **ExecutionPermit issuance for the successor.** `SuccessorCredentials::issue` has no route. Without it there is also no permit or `LaunchAuthority` for `aq_session_host::SessionHost::launch` behind `SessionHostStart`.
3. **The aq-git dirty+untracked snapshot.** `archive.rs` (`aq-hibernation-source-v1`) stays the worker-local snapshot until aq-git publishes the operation.
4. **An agent-side surface for `request_checkpoint`, `close_input` and `reconcile_effects`.** The `AgentLifecycle` port has no AQ route or harness API yet.

## Limits

- Crash recovery resumes after the last journaled step. A crash after a port effect but before its journal write repeats that effect. The production guardian and backend ports are idempotent as described above. The TODO ports must be idempotent too, and AQ dedups packets by message id and digest.
- The source snapshot is a worker-local format (`aq-hibernation-source-v1`, at most 256 MiB, regular files and directories only) until aq-git publishes a dirty/untracked snapshot operation.
- `LocalGuardian` has no dedicated unit test. Building a real `GuardianIdentity` needs a live guardian launch, and the acceptance test exercises the `WriterGuardian` seam with a fake.

## Adapter verification (clear-crest-61.5.1)

`suspend_wake_through_http_lifecycle_adapter` (`crates/aq-worker/tests/hibernation.rs`) drives suspend and wake through the real `HttpLifecycleApi`. It runs against an in-process axum fake of both routes on loopback, backed by `ConformancePeer`. It also uses the real `NodePorts` over `FakeBackend`, and fakes for the guardian, agent, retention and launcher. The test checks:

- The suspend directive arrives over GET, and the attempt reaches `RetainedSuspended`/`ParkingRecorded`. The sandbox is `Stopped`, the disk is present, and two packets were posted.
- A replayed suspend returns the same receipt.
- The disk-release directive arrives over GET, and `release_disk` leaves the sandbox `Destroyed`.
- The successor fetches the continuation over GET, hydrates the workspace and launches once.
- The ack, posted over HTTP, opens the gate.
- A reused message id carrying a different body gives a 409 `LifecycleStatus`, and an unknown bearer gives a 401.
