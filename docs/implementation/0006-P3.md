# Spec 0006 phase 3: the agent channel (worker side)

Spec: aq-server `docs/specs/0006-agent-channel.md` (approved 2026-11-06), §5 (the channel), §8 (security) and §10 phase 3. Branch `chan/worker-proxy`.

## What was built

### `crates/aq-agent-channel` (new crate)

The forwarding code lives in its own crate. It is shared by the channel and the B6b proxy, and it keeps the aq-worker lib under its line ratchet.

- **`AgentChannel`**: the per-attempt Unix-socket proxy (§5.1).
  - **Credential first.** `open` asks a `CredentialIssuer` for the attempt's credential before the socket exists. If any step fails, the error is `agent_channel_unavailable`.
  - **Socket.** It creates `<root>/channels/<attempt>/` with mode 0711 (the parent is 0700) and binds `aq.sock` through the directory's descriptor (`/proc/self/fd/N/aq.sock`), so long node state paths never hit the 108-byte `sun_path` limit. The socket is 0666: the agent reaches it as "other" (rootless userns or another uid), and only this attempt's bind mount exposes it.
  - **Forwarding.** It forwards only `/api/v1/commands[/…]`, `/api/v1/operations/…` and `/v1/agent/…`. Other paths get a typed `channel_refused` (403), including `/v1/worker/`, `/v2/worker/` and `/v1/execution/`. Dot segments and percent-encoded `.`, `/`, `\` and NUL are refused, so URL normalization cannot move a forwarded path into a refused namespace.
  - **Headers.** It removes any caller `Authorization`, `cf-access-*`, hop-by-hop and Connection-nominated headers. It injects `Authorization: Bearer aqa_…`, plus Access headers when configured (none for the local MS1 server).
  - **Framing.** B6b's rules apply: fixed origin, no `Transfer-Encoding`/`Upgrade`/`Expect`, 16 KiB head, 4 MiB bodies, identity encoding, no redirects, 16 concurrent requests. A response that echoes the credential is refused (502 `channel_upstream_failed`, effect `unknown`).
  - **Custody.** The credential is held in memory only (`Zeroizing`). It never reaches argv, env, `/aq/in`, `/aq/out`, labels, the pane or logs. Logs record attempt, method, path (without the query), status and duration.
  - **Rotation.** It rotates at two thirds of each credential's life through the `expected_credential_version` fence. A credential that already reaches `not_after_ms` (the earlier of grant expiry and hard deadline) is never renewed. An unavailable issuer is retried every 5 s. Issuance runs under the node credential, so a late rotation (a stalled node) still renews; calls in the gap get the server's `session_expired`.
  - **Close.** It closes on `close()`/`stop()`, at `not_after_ms`, on a refused rotation, and when the server answers `session_revoked` (that response reaches the caller first). In-flight calls get 1 s. Then the socket directory is removed, so later calls fail at connect (`channel_closed` in the CLI).
  - **Restart.** The channel holds an exclusive `flock` on its directory for its whole life. `sweep(root)` removes only directories nobody holds, meaning their node process died. Live channels and foreign entries are left alone. `open` reuses an existing directory and rebinds a stale socket, as readoption would need (§5.4).
- **`CredentialIssuer`** is the small issuance interface: `issue(expected_version) -> Issued { token, version, expires_at_ms }`. Its errors are `Refused(code)` (terminal) and `Unavailable` (retry).
  - **`NodeIssuer`** is the production issuer: `POST /v2/worker/agent-session` under the node bearer, with `identity` + `attempt` + `expected_credential_version`. The response must carry `version == expected + 1`, an RFC 3339 `expires_at` and an `aqa_` token.
  - Phase 2 seals grants into the same `agent_launch_bindings` row this route issues from, so the call does not change when grants land.
- **`LoopbackProxy`** is the B6b `AqApiProxy` on the same core, with unchanged behaviour: agent `Authorization` passed through, Access injected, Host must equal the listener authority, generic empty 502.
- **`holds_agent_credential`** is the leak scan: `aqa_` followed by at least 32 base64url characters. The server issues 43. The length bound keeps AQ's own source text (`starts_with("aqa_")`) from failing an attempt that edits AQ.

### aq-worker wiring

- **Mount kind.** `CreateRequest.agent_channel` (serialized only when true, so existing request hashes are unchanged) plus `DockerLocalConfig.channel_root`.
  - `create_body` adds one fixed bind: source `<channel_root>/<attempt>`, target `/aq/channel`, read-write. The request only says yes; it never names a path.
  - `create` refuses when the directory is absent.
  - Config validation refuses a relative or daemon-exposing root, and any alias or material path at or under `/aq/channel`.
  - boat refuses the flag, because remote backends run the channel in the sandbox (§5.3).
- **Launch** (`native/launch/claude_docker.rs`):
  - `ClaudeDockerHostConfig.agent_channel` defaults to `required`. Only an explicit `"disabled"` launches without a channel; it is serialized only when disabled, so existing profile digests are unchanged.
  - The executor hands the profile its server origin and node credential (`ChannelIssuance`, memory only).
  - Bootstrap opens the channel before the driver config is written, using the attempt's `SessionIdentity::Remote` and `not_after = min(deadline, hard)`. It parks the channel in the entry's `Physical` beside the scoped transport and passes `agent_channel` plus `channel_root` to the driver.
  - Failure fails the bootstrap, and the executor reports "did not establish Running".
- **Stop.** `stop_now`/`cancel_transport` closes the channel on cancel, stop and bootstrap failure. `finish_stopped_transport` drops it, which removes the directory. The profile sweeps stale channel directories at load.
- **Driver** (`sandbox_driver.rs`):
  - `channel_ready` checks that `<channel_root>/<attempt>/aq.sock` is a socket before the backend is contacted or the sandbox exists; otherwise the error is `agent_channel_unavailable`.
  - The driver then requests the mount, writes `AQ_CHANNEL=unix:/aq/channel/aq.sock` into `/aq/in/env` and appends `CHANNEL_NOTE` to the prompt.
- **Leak guard.** `holds_secret` (the exact login token, or any agent credential) now drives the transcript, pane-line and copy-back (file data, paths, link targets) checks. A hit withholds the line or refuses the copy-back, as for the login token.

## Acceptance (§10 phase 3)

- **Live: `tests/claude_live/channel_live.rs` — `container_calls_whoami_through_the_agent_channel`** (`#[ignore]`; needs `AQ_SANDBOX_SOCKET`, `AQ_MS1_TEMPLATE_IMAGE`).
  - **Setup.** The real `sandbox_driver::run` drives a real docker-local (rootless podman) sandbox on the template `localhost/aq-i4a-claude-rust@sha256:194e11f5…`. The real `AgentChannel` serves the socket with a fixed-credential issuer, and a stub aq-server sits behind it. The agent is a bash and curl script in place of Claude.
  - **Results** (evidence in [`0006-P3-evidence/`](0006-P3-evidence/)):
    - `whoami` returns 200 with the attempt principal. The agent sent `Authorization: Bearer spoofed-by-the-agent`; the stub saw only the attempt credential.
    - `/v2/worker/agent-session` returns 403 `channel_refused` and never reached the stub.
    - The server's `session_revoked` (401) reaches the agent. The channel then closes and its directory is removed, and the next `whoami` fails at connect (curl exit 7, HTTP 000).
    - `AQ_CHANNEL=unix:/aq/channel/aq.sock` is in the agent environment.
    - Zero `aqa_` substrings appear in the transcript (`claude.jsonl`) or in any copied-back file.
    - The driver exits 0.
  - **Command:** `AQ_SANDBOX_SOCKET=/run/user/1000/aq-sandbox/podman.sock AQ_MS1_TEMPLATE_IMAGE=localhost/aq-i4a-claude-rust@sha256:194e11f54fbe104734166ec219f5ac13b2e54055fae01f6c3ce264a915f172a4 AQ_CHANNEL_LIVE_EVIDENCE_DIR=… cargo test -p aq-worker --all-features --test claude_live channel_live -- --ignored`
- **CI: `aq-agent-channel` unit tests:**
  - credential injection with spoofed headers removed, node paths refused without reaching the server, credential echo refused, and modes 0711/0666;
  - rotation invisible to callers, and a refused rotation closes the channel (independent of timing: 40 sequential and 60 parallel runs green);
  - server revocation closes the channel and removes its directory;
  - open fails closed with no socket, the grant end closes the channel, and the sweep spares live channels and foreign entries;
  - `NodeIssuer` request shape, the version fence and error classes;
  - the path rule and the guard's shape.
- **CI: `docker_local_backend` — `agent_channel_mount_is_fixed_to_the_attempt_directory`**: the fixed mount source and target, refusal without a directory or a root, unchanged request hashes, and config refusals.
- **CI: `sandbox_driver::tests::channel_is_required_named_in_env_and_its_credential_guarded`**: no socket means `agent_channel_unavailable`; `AQ_CHANNEL` is in the env; `CHANNEL_NOTE` is in the prompt; a credential in a file, the transcript or the pane is caught; source text `starts_with("aqa_")` is not.
- The B6b (`sandbox_security`) and B7 (`agent_access`) tests pass unchanged on the shared core.

## Pending on the server phases

- **Real `whoami`.** It is not merged in aq-server; no `chan/*` branches or PRs existed when this was written. Re-run the live test with the stub replaced by a real server once phase 1 (`/api/v1/commands/whoami`) lands.
- **Real issuance.** `NodeIssuer` is tested against a stub of today's `/v2/worker/agent-session` contract. The server issues only for a `GraphActive` attempt with a sealed binding and a configured agent-access runtime. A node whose server lacks these now fails Claude docker-local launches with `agent_channel_unavailable`, unless the host profile sets `"agent_channel": "disabled"`. When phase 2 seals grants, confirm that the issuance response shape is unchanged.
- **Error codes on the server side.** Phase 0/1 refusal codes (`grant_missing`, `scope_denied`, …) pass through the channel unchanged. Only `session_revoked` has channel meaning (it closes the channel).
- **Not in this phase:**
  - CLI channel mode (`AQ_CHANNEL`, mapping a connect failure to `channel_closed`) is phase 4;
  - shipping `aq` in the template is phase 4;
  - the boat in-sandbox channel is phase 7;
  - readoption keeping channel directories alive across a node restart (today `reconcile-native` stops the sandbox and the attempt closes).
