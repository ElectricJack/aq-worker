## Adoption and source admission

The sandbox runner links exact local versions `aq-observation =0.1.0`,
`aq-observation-engine =0.0.1` and `aq-observation-redb-prototype =0.0.5`.
After session-host launch, the trusted `HarnessAdapter::transcript_source`
hook receives that exact `LaunchIntent`. It supplies an exact root/member,
native session key, format and logical provider/account reference. The runner
matches the descriptor to the launch ID/session and manifest binding before
starting collection. Adapters without metadata support record
`observation-incomplete`; they never trigger fallback discovery. This extends
the existing generic sandbox runner integration seam; harness-specific launch
adapters must supply their own exact launched transcript metadata.

Admission accepts only canonical paths within the prepared workspace or session
directory. It invokes bounded exact-member discovery (one member), verifies
the native session metadata, and persists the original inode/root identity and
permit. It never enumerates a provider home or chooses a session by cwd/time.
Symlinks, traversal, foreign native IDs and file replacement cannot retarget
collection. The source owner comes from the launched agent UID. Existing
same-user callers retain their original policy when no explicit owner is set.
This small source-permit extension requires the fresh targeted source/reader
checks below; previous package qualification is not claimed for changed code.
The store's source-code policy digest changes with these adaptations. H1 uses
fresh stores; earlier experimental store markers remain refused rather than
migrated or silently reseeded. No compatibility/migration claim is made.

## Durability and control

`Collector` uses format5's transactional `collect_file`: facts (or an explicit
loss gap), normalizer state and consumed cursor commit together. An incomplete
last line remains unconsumed. `prepare` persists the replay packet; receipt
validation happens before opening an acknowledgement transaction. A malformed
or mismatched receipt cannot discard a packet or poison subsequent replay.
Reopening the same source resumes its cursor and preserves byte-identical
pending packets, even if the exact transcript has disappeared. No replacement
file identity is admitted on reopen. Missing input retains the cursor and
reports incompleteness. An empty store left between creation/attachment can
complete admission on retry; a foreign source store is refused.

`ObservationTask` owns all collection and store I/O on a dedicated thread.
`SandboxChannels` supplies a separate connection pool sharing the sandbox's
delegated permit and authority-loss state. Only bounded lifecycle batches are
posted to `POST /v1/worker/observations/batch`; every event must match the
sandbox session/attempt. Only a matching lifecycle receipt advances delivery.
No node credential is used. Server registration/accounting remains H2.

The runner signals telemetry stop before stopping the host and never joins the
telemetry thread on its renewal, cancellation or stopped-proof path. A held
HTTP request is cancellable; an unacknowledged packet stays durable. The
explicit recovery entrypoint is reopening `Collector`/`ObservationTask` with
the same launch descriptor and renewed authorized channel. This does not
relax the runner journal's existing refusal to relaunch an executed attempt.

State changes are coalesced into a small atomic runner-private status file;
repeated idle state emits no ordinary-state traffic. Missing/unsupported
metadata is journaled; source-held, source-unavailable, delivery-unavailable,
store-unavailable and stopped-incomplete states are explicit. Stopping is
conservatively incomplete: it does not certify that a live transcript has no
unread tail. Status and observations grant no execution authority.

The unchanged fixture limits are enforced: 64 KiB events, 256 KiB batches,
16 MiB logical telemetry data, 64 MiB physical store file and the store's
16-source ceiling (this runner attaches one source). `GapAndHold` preserves
the reserved loss gap under overload and holds the source rather than silently
advancing. The normalizer tracking bound is 4096. Usage facts retain numeric
native counters and provenance, excluding prompt/tool bodies.

## Real Codex qualification

Decision: qualify the existing rollout reader, format
`codex-rollout-jsonl-67f0994`; no exec-JSON reader was introduced.
`codex --version` reported **0.166.0**. A real current launched Codex run's
exact session ID was resolved through the local thread index to its rollout
path. Only that path was read. The committed fixture
`crates/aq-worker/tests/fixtures/codex-real-0.166.0.jsonl` contains seven
sanitized real records: session metadata, task start, turn context and four
cumulative token-count snapshots. Numeric counters and model were preserved;
session/turn IDs and timestamps were replaced, and cwd, instructions, git,
environment, account data and raw content were dropped. The sanitizer accepts
an explicit input path and never discovers files. Hashes and capture details
are in [provenance.json](H1-evidence/provenance.json).

Both pinned readers process the same real excerpt without gaps and agree on
event classes, source cursor ranges and native usage fields. Their semantics
artifacts deliberately retain separate parser version/digest identities.
