## Contract decisions

- One async `PlacementBackend` contract; operation results distinguish backend failures from confirmed stopped-writer evidence. An absent inventory entry is uncertainty, not evidence of destruction.
- Scope is node/boot/attempt plus backend kind/id. Create uses a deterministic node/attempt name; conflicting replay is rejected. The digest is immutable and exact; no tag resolution occurs here.
- Private material is an opaque, zeroized, redacted control-channel payload. The backend interface exposes no secret-bearing argv or environment fields. Real adapters must deliver to runner-only storage and enforce permissions.
- Retention receipts/operator release references authorize only their bound sandbox. They are assertions by the trusted controller, not cryptographically verified receipts; B5a owns validation against central retention.
- Reconciliation is a pure recommendation. It does not persist, schedule sweeps, rebind boot authority or release capacity. Adoption means recording/monitoring an exact owned match, not granting runner authority.
- Unknown, inconsistent or foreign inventory cannot authorize deletion. Deadline expiry recommends stop while keeping disk; subsequent retention/reclamation policy belongs to B5b.
- The conformance fixture adapter supplies fault injection and fixture handoff for real backends. C1's fake runs deterministic in-memory fixture effects; it does not qualify real container/VM execution, hostile-code isolation or transport security.

## Interfaces for follow-on tasks

`aq_worker::backend` exports `PlacementBackend`, `BackendKind`, `Capability`,
`CreateRequest`, `PrivateMaterial`, identity/inventory types, `Confirmation`,
`StoppedWriterProof`, `DestroyAuthorization`, lifecycle types and `FakeBackend`.
The existing controller journal and `STATE_FORMAT` are untouched.

A create request binds node, boot, attempt, a deterministic node/attempt name,
canonical `sha256:` digest, required capabilities and absolute hard deadline.
Backends must map that digest to the corresponding registry/template artifact;
there is no mutable tag resolution in this interface. Missing capabilities are
explicit errors. Optional archive/resume/fork default to unsupported.

B5a should fsync `LifecycleRecord::intent` before calling create, then persist
`record_created`. Persist stop/archive confirmation, `record_preserved`, and
finally `record_destroyed` with retention authorization. Failed transitions do
not mutate the record. Confirmation of stop can establish writer quiescence,
but disk retention is a separate condition; no method here releases capacity.

B5b should pass a complete, scoped `list_owned(node_id)` entry or a journal-matched
inspection to `reconcile`. Missing inventory means `Hold`. `Deadline::at` treats
the exact deadline as expired. Unknown authority and expiry stop or preserve;
only matching retention authorization plus confirmed quiescence can recommend
destruction. Boot mismatch holds for explicit server re-adoption. `Adopt` only
recovers monitoring/journal identity; it never starts a runner.

For C2/C7/C8, enable `aq-worker/test-support` and implement
`backend::conformance::BackendFixture`, supplying the real backend, a unique
attempt request per case, fixture material, injected API faults, output
observation and retention verification. Call `conformance::run_all` from the
backend's test. Individual scenario functions are also public. The fixture must
own a dedicated test scope and clean it on panic. Tests exercise lost create
responses, unknown inventory, failed destruction, unretained work, expired
deadlines, and the full create/provision/run/observe/handoff/destroy path.
