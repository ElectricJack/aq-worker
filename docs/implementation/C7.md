# C7 — Boat placement backend

C7 implements the Boat adapter and local qualification. **Live acceptance is pending**: this worker session has no approved `BOAT_LIVE_CONFIG` / `BOAT_API_KEY`, dedicated attempt/build scopes, or scanned real saved snapshot. HTTP-double success is not real-provider qualification. No Boat VM, snapshot, enrollment, or deployment was created in this session.

## Change and boundaries

`backend/boat` implements C1 `PlacementBackend` using authenticated HTTPS at `https://boat.dev/api/v1`. The key comes from a mode-0600, same-owner regular node-local file opened without following symlinks. It has a redacted Debug implementation and is never serialized, logged, passed to commands, or included in VM environment/material. Requests disable redirects and bound request time, response size, polling, inventory pagination, and journal size. Failures omit provider bodies and URLs because these may contain credentials.

The adapter advertises `VmIsolation`, `SuspendSnapshot`, and `PersistentDiskDuringAttempt`; it refuses `NestedDocker`, host mount aliases, missing resource reservations, and allocations larger than large. Size selection is small (<=2 CPU/4GiB), default (<=4 CPU/8GiB), large (<=8 CPU/16GiB). It creates private VMs from scanned saved templates with `noEnv:true`, empty env, snapshots enabled and monitoring disabled. It never invokes prompt/AI proxy, SSH, desktop, hosting, or port-publishing endpoints.

Each VM gets a deterministic `aq-{node UUID without hyphens}-{attempt UUID without hyphens}` name and a create idempotency key. The locked, atomically replaced/fsynced journal records the complete request before create, then the provider ID, material/start state, and deletion-operation ID. A failed durable write fences the adapter until restart. A lost create response remains discoverable through paginated inventory. Local filtering checks both the exact node/attempt name grammar and the dedicated attempt org, even if the server ignores its name filter. Old boots remain discoverable. A changed request cannot reuse a name. Vendor labels are not authority.

An unrecorded prefixed VM has an explicitly unknown (nil) boot and placeholder digest/deadline; it is an orphan, never an adopted grant-bearing attempt. Controller journal validation permits unknown boot only for Boat orphans. The sweep stops and preserves these VMs. After explicit retention/operator release, an orphan can be deleted through a separate durable orphan deletion record; it never acquires an invented CreateRequest or boot. The same completed-purge proof is required across restart.

Every create/update supplies a positive explicit TTL. The target is the original hard deadline plus 5 seconds, rounded up by <1 second. The configured maximum API request time is subtracted before conversion to avoid adding that timeout to the bound. Short/expired deadlines are refused, and updates above the original deadline are refused. Remote auto-stop backs up the controller/grant deadline; it does not issue execution authority. Model control traffic with >=250ms RTT. Provider uncertainty still requires reconciliation; no terminal latency result is claimed.

After VM readiness, the adapter waits for Docker restoration and verifies the exact pinned RepoDigest before creating the OCI container. Per-fork IPv4/IPv6 firewall setup retains Boat control TCP 8911, loopback, established traffic and outbound WireGuard; no public hosting is enabled. The agent runs inside the OCI container with all capabilities dropped, no-new-privileges, PID/CPU/memory/swap limits, a private work volume, bridge networking, no restart, no published ports and no host/socket mounts. The image's fixed command is used unless the operator supplies a fixed `runner_command`, shell-quoted as individual argv elements. This is node configuration, never assignment input. The B6b runner owns its existing agent privilege transitions; the agent gets no VM root or Docker socket.

Private attempt material uses authenticated file upload of a tar into a mode-0700 VM directory, then `docker cp` into `/aq/private/material` with directory 0700/file 0600/root ownership. A trap removes the staging directory. No private bytes are placed in command text or env. Work can be read through the container while running, or directly from `__dockervol__/{attempt-name}-work/...` in the archived snapshot without resuming writers (4MiB control response cap).

Stop/archive requests non-forced stop and waits for archived state, snapshot availability, and completed stop status when supplied. It preserves the disk and attests zero processes only from that authoritative archived observation. Destroy requires matching retention/operator authority, confirmed stop, permanent DELETE, a durably recorded deletion operation observed `completed`, VM GET 404 and empty/absent automatic snapshot inventory. HTTP 202, disappearance, pending purge, timeout, API failure or contradictory state never constitutes a destroy proof. Permanent deletion covers automatic attempt snapshots; saved build templates are independent and never deleted by the attempt adapter. A lost deletion reply before its operation ID is journaled remains uncertain and needs operator recovery. Resume/fork of attempt snapshots is explicitly unsupported; warm starts stay deferred.

`BackendError::Unavailable` distinguishes API, transport, rate and capacity failures. Controller create/material/start paths persist `RefusalReason::BackendUnavailable` while retaining the effect intent and reservations. Tests inject outages both before and after a create side effect; recovery discovers/stops any resulting VM and preserves disk. The exclusive run config selects exactly one `docker_local` or `boat` backend, validates advertised template digests, and checks the Boat node ID against enrollment. The existing B2 production provider fence is unchanged.

## Template materialization

`aq-worker template boat-materialize NAME@VERSION --build-config /private/boat-build.json --oci /private/image.oci.tar --output /private/new-evidence-dir` extends C3b. Installed workers embed the tool and scanner; a source checkout is not required. Example build config (references only, no key bytes):

```json
{
  "schema_version": 1,
  "role": "boat-template-build",
  "build_org": "team_builds",
  "attempt_org": "team_attempts",
  "key_file": "/private/boat-build-key",
  "builder_identity": "aq-template-builder",
  "allowlist": "allowlist.json"
}
```

The allowlist is relative to the config directory. The tool requires an existing C3b allowlist entry and independently scans the actual OCI archive, checks its manifest digest against that entry, creates a bounded/no-env build VM in a separate org, pulls the exact public digest, verifies RepoDigests, and creates a stopped keeper container so Boat retains the used image. No registry credential/config is forwarded; private-registry pulls are deliberately unsupported by this initial materializer.

It saves a fresh unique snapshot name, waits for ready, downloads that immutable snapshot's captured filesystem, and scans every captured tar member with C3b credential path/content/link checks and archive bounds, without extracting members to host paths. Boat CLI config paths are now sensitive paths too. Stock base files omitted by Boat's snapshot export are not claimed scanned; the OCI is independently scanned in full by C3b. The worker's newly adjacent public Serde labels required one exact format-context exception in the existing token pattern; regression tests verify changed context and adjacent real tokens still refuse.

Only a successful scan permits atomic, locked allowlist publication under `entry.materializations.boat`: OCI digest, unique saved name, immutable snapshot ID, scan policy, snapshot archive digest, build org/identity/time. C3b validation rejects digest mismatches and missing scan evidence. Reviewable scan report and archive remain in the private output directory. Build VM deletion is requested in a finally block, with the 30-minute TTL bounding compute if create/cleanup replies are lost. Failed captures are never allowlisted and the tool requests removal of their saved name. Cleanup failures are errors, not successful qualification.

Derive the trusted node config's `boat.templates` from the reviewed allowlist: `image=entry.image_reference`, `digest=entry.image_digest`, `saved_snapshot`, `snapshot_id`, and `scan_policy` from its Boat materialization. Set `boat.node_id` to that separate enrolled node's ID, `attempt_org`, `template_org` (the distinct build org), absolute `journal_path` and `key_file`, plus optional fixed runner argv. The adapter checks the immutable snapshot ID behind the saved name before create and verifies the OCI digest inside the fork. Never replace an admitted saved name; materialize a new unique name/version instead. Protect snapshot-write permission on the build side. The attempt key needs explicit read access to the source snapshot as well as create access to its destination; organization billing selection is not a credential security boundary.

## Provider facts and operational limits

Reviewed 2026-11-02 from Boat's official v1 documentation; these are documented behavior, not measurements:

| Topic | Source and consequence |
|---|---|
| Create/fork | [Create](https://docs.boat.dev/api/reference/sandboxes/create-sandbox), [fork](https://docs.boat.dev/api/reference/sandboxes/fork-sandbox): POST create `from` uses a saved snapshot; explicit resource type/TTL/no-env overrides inherited settings. C7 uses create-from-template, not attempt fork. |
| Deadlines | [Update](https://docs.boat.dev/api/reference/sandboxes/update-sandbox): TTL is relative to the update, 1–2,592,000 seconds (trial has stricter limits). Omitted/default/off TTL is never used. |
| Stop / retention | [Stop](https://docs.boat.dev/api/reference/sandboxes/stop-and-archive-sandbox), [retention](https://docs.boat.dev/llms.txt): stop removes compute and retains the disk. Automatic stopped data expires after 14 days; save independently for longer retention. C7 must hand off within retention bounds. Force stop can discard changes and is not used. |
| Delete | [Deletion lifecycle](https://docs.boat.dev/data-retention/delete): permanent deletes require `X-Ascii-Confirm-Delete`, return 202, and must be followed through `/deletion-operations/{id}`. Data can disappear from lists before purge completes. Saved snapshots are independent references. |
| Snapshot timing | [Save](https://docs.boat.dev/api/reference/snapshots/save-saved-snapshot): save returns `saving`; capture may take minutes. Poll until ready/failed. No measured capture time is available here. |
| Restore timing | [Readiness](https://docs.boat.dev/readiness): vendor describes readiness in a few seconds; Docker/content hydration follows later. C7 waits for Docker and does not treat this as a measured resume or terminal-latency result. Attempt resume remains unsupported. |
| Captured files | [What is saved](https://docs.boat.dev/snapshots/whats-saved): used images, containers and Docker volumes survive; unused images/build cache and `/tmp` do not. Previously running containers can restart, hence the stopped keeper and no attempt resume. |
| Firewall | [Firewall](https://docs.boat.dev/hosting/firewall): no network-rule API; firewall state is not saved. Reapply on every fork/resume, preserve control TCP 8911 and outbound WireGuard. Container agent has no host firewall/root access. |
| Scopes | [API key scopes](https://docs.boat.dev/api-keys/scopes): attempt key needs `sandbox.create/read/update/stop/delete`, `exec`, `file.write`, `snapshot.read`, scoped to dedicated destination/source. Build key additionally needs `snapshot.write`. No `agent.prompt`, `ssh`, `desktop`, `host`, `account.admin` or wildcard. Deletion-operation visibility must be verified during live qualification; no broad account grant is assumed. `noEnv` removes the in-VM CLI API key; a host-side ASCII_TOKEN can remain and is not forwarded into the OCI container. |
| Account limits | [Template scaling](https://docs.boat.dev/snapshots/templates): documented paid tiers allow 100/300/1,000/2,000 simultaneous VMs and 12/30/65/90 starts per minute (also hourly/daily limits); trial is 2 concurrent, 5 starts/minute. Capacity/rate refusals must not leave running untracked VMs. No paid-plan capacity is qualified here. |
