# WRK-15 bounded-delta checkpoint

This candidate adds a bounded normalization engine and a new-store redb adapter. It does not replace the qualified JSON reference or integrate a worker runtime. The source inventory and retained local logs are in [WRK-15-delta.json](WRK-15-delta.json). Clean standalone qualification passed at source commit `80d79133e720ec684a0724b90b519cb0acacf35a`; both extracted candidate packages plus the unchanged reference passed 82 tests, strict lint, formatting, artifact drift and 90 measurement repetitions per configuration. The clean worktree stayed clean. Archive hashes and commands are retained in the JSON inventory and `WRK-15-delta/clean-qualification.json`.

The engine reads indexed source-scoped rows and produces a bounded delta. Collection commits the source cursor, reader anchor, normalization context, dedupe rows and matching facts together. A 32-record batch uses one transaction rather than 32 fsync pairs. File-backed and generic batch APIs cannot silently bypass each other's provenance checks. DTO sources use separate durable record cursors. Boot changes fence old live collection; old committed packets remain deliverable, while old-source reparse requires verified immutable retained bytes.

Frozen packets and mutable retry metadata occupy separate rows. Prefix selection counts actual canonical record/envelope bytes and seals the final packet once. A boundary test compares the resulting exact wire prefix to the reference greedy sealing algorithm. Delivery, ACK and collection never scan unrelated retained history. Startup validation deliberately audits retained rows.

The checkpoint passes 16 engine and 31 row-store tests, strict package lint, artifact drift and formatting. Fault matrices cover 272 injected IO-error boundaries and 272 actual process exits, including the split packet/retry rows, 32-record collection, file-backed cursor/facts and reparse stages. Reopen must expose the old or new consistent projection. These process-exit tests do not certify hardware power-loss behavior. Source pathname/root replacement is refused before writes to the held database inode.

The preserved reference's normalizer semantics are covered by ten ported tests and four differential/bounded-delta tests; additional row-store tests cover quotas/reserved gaps, boot fencing, DTO cursors, file partial/rotation/truncation/identity checks, history enrollment, corrections/reparse, operation conflicts and retention. The frozen reference source remains unchanged. Native source fixtures are sanitized synthetic inputs with format provenance, not qualification of any selected released CLI.

## Measurements and bounds

The retained 90-repetition measurement uses actual file framing, normalization and transactional collection, then delivery/ACK, with synthetic Claude-shaped input and no provider calls. The near case starts with 5,120 retained calls and 12,784,487 logical bytes. Population is excluded from timing. The JSON inventory provides p50, nearest-rank p95, max, written bytes and sync counts; raw samples are retained beside it.

Definitive clean-archive near-case p50 collection of 32 records is 20.56ms with two syncs; prepare is 15.58ms, retry send 11.74ms and ACK 13.61ms. Near-case p95 values are 25.65/20.42/14.81/16.18ms respectively; max send/ACK reaches 94.28/82.72ms. Earlier same-code local samples were faster (11.33/7.72/4.60/6.16ms p50), showing host/IO variability; neither run is a service latency guarantee. Written-byte medians remain identical across the two runs. Retry writes fall from 86,656 to 25,216 median bytes after splitting immutable packets from retry state. Prepare previously cost about 40ms with repeated prefix sealing. The new small/near timings are comparable within each run; this is evidence against unrelated retained-history scans, not a universal latency bound.

Database size grows from 23,449,600 to 46,895,104 bytes during the 90-cycle near run under a 67,108,864-byte physical cap. Logical retention is capped at 16MiB and cache at 4MiB. This leaves finite observed headroom, but longer-cycle growth, compaction/reclamation and operational headroom remain open. Raw source retention and whole-directory disk bounds are separate obligations. No claim of production scalability or deployment readiness follows from these samples.

## Next gate

The current `VerifiedNewStore`/boot callbacks are explicitly prototype-only. They do not implement the frozen central Prepared/Activated handshake. Next work persists a LocalIntent before prepare, a creation marker before database creation, and an activation intent before activation; sources and collection remain barred until activation is durable. Replayed initial receipts must never recreate a missing active spool, even when the central accepted cursor is zero. Missing/corrupt stores hold for explicit recovery rather than reseeding.

The retained admission review reproducer describes two pre-freeze draft bugs, fixed before admission 0.1.0 was published locally. It is historical review evidence, not a failure of the frozen contract. Parser artifacts remain distinct from stable owner accounting category policy; worker claims cannot establish fresh-zero baselines, cross-session dedupe, budget resets or complete accounting.
