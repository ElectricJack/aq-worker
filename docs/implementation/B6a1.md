## Delivered boundary

`aq-worker sandbox-run --manifest PATH --state-dir PATH` accepts the private
local frozen handoff. Production HTTP wiring is deliberately unavailable: the
command validates its inputs and explicitly refuses before any journal, guardian,
writer, registration, offer poll or acceptance. The callable runner is
`aq_worker::native::runner::sandbox::run`, exercised with real guardian/tmux and
`aq-fixture-agent` processes through one typed `RunnerTransport` trait.

Supervisor instruction `msg-d369fb8d69a14dffa0c924bab36180da` authorized this
fixture-backed transport boundary because B2 owns the server runtime and no
runner endpoint/consumer contract existed. HTTP wiring belongs to B2/B6a2.
The local receipt types are library observations, not invented HTTP schemas.
These fixtures do **not** prove server compatibility or qualify a production
provider adapter.

The transport receives existing `WorkerConfig` authentication, as required by
this task's interim exception. The delegated credential is a separate in-memory
input. Neither credential enters the frozen manifest, journal or harness
command. B6a2 owns permit-only transport authentication.

## Execution and retention

- The frozen handoff binds the canonical launch manifest, phase execution
  origin, state directory device/inode/path, launch identity, kernel boot and
  original send/receive clock observations. Loading it never creates a fresh TTL.
  It cannot restore execution through the existing native recovery journal.
- Atomic creation of `state_dir/sandbox-run`, fsynced before launch, fences both
  concurrent consumers and replay. No outcome deletes the workspace, evidence,
  consumed marker or host directory; a second invocation cannot launch.
- `native::launch::sandbox` delegates physical hosting to `aq-session-host`.
  The existing subreaper creates a private tmux server inside its ownership
  boundary and owns every pane/descendant. No shared tmux server is joined.
- Renewal defaults to 15 seconds while Running. Local permits are capped at
  120 seconds, the delegated permit, the original execution hard deadline and
  the manifest wall limit. Deadline checks use Linux `CLOCK_BOOTTIME`, including
  while the transport future stalls. Transient loss/re-adoption extends nothing;
  explicit refusal or elapsed authority triggers stop and preservation.
- Renewal requests retain their operation identity across transient failures.
  The B1 validator checks correlation, binding, nonce, revision and trusted
  prior grant context. New local authority is persisted before guardian install.
  Late replies cannot revive expired authority. A natural exit racing renewal
  installation still requires physical proof and handoff receipts.
- Pane/EOF/tmux disappearance is not proof. The runner requires the exact host's
  opaque `StoppedProof` with kernel `ECHILD` before retention. Failed stop proof
  leaves resources protected and never invokes retention or completion.
- `StoppedAttempt` and `RetainedAttempt` cannot be deserialized or constructed
  by transport callers. The latter is produced only after source and result
  receipts match the attempt and the result digest matches the exact retained
  stopped evidence. Both receipts are fsynced before `finished`; its matching
  acknowledgement is fsynced before `RunOutcome::Finished`.
- The trusted transport must authenticate central receipts and durably retain
  actual artifacts. Local receipt validation does not authenticate a server.
  The fixture central store fsyncs source-output bytes and stopped-result evidence
  before issuing its test receipts; this is not a production Git export service.

Prepared workspaces, context material, credentials profiles and a trusted
`HarnessAdapter` enter through the existing host library. This change adds no
hydration, terminal/observation transport, container backend, OS-user separation,
Codex qualification or node controller. It makes no hostile shared-kernel
isolation claim. `aq-session-host` remains a reusable library for F1a.
