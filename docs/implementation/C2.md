# C2: `docker-local` backend with a dedicated rootless sandbox daemon

Task: `calm-delta-18.2`. Base: `dc62cfc0faf2109485b1c9f17a024f6fcb37ebd5` (C1, equal
to `origin/main` at close). Plan: `docs/superpowers/plans/2026-11-02-C2-docker-local-backend.md`.

## What was built

`aq_worker::backend::docker_local::DockerLocalBackend<T: DockerTransport>`
implements C1's `PlacementBackend` against the Docker Engine API (v1.44 paths)
over a Unix socket.

| Area | Where | Behaviour |
| --- | --- | --- |
| Config | `src/backend/docker_local/config.rs` | `DockerLocalConfig{socket, templates, mount_aliases, runner_command, material_path, material_uid/gid, api_timeout_ms (10 s), stop_grace_secs (10), max_read_bytes (1 MiB)}`. `validate` rejects `/var/run/docker.sock` and `/run/docker.sock` by path, canonical path and inode, plus non-sockets, sockets not owned by the worker's euid, and mount aliases that would expose any daemon socket or overlap `/aq/work` or the material directory. |
| Connect | `mod.rs` `connect` | Requires `GET /info` `SecurityOptions` to contain `name=rootless`. A rootful daemon is refused even on a dedicated socket (SBX10, 0005 §5.1). |
| Launch policy | `policy.rs` `create_body` | The whole create body is fixed. `Privileged=false`, `CapAdd=[]`, `CapDrop=[ALL]`, `Devices=[]`, `no-new-privileges`, `Env=[]`, `NetworkMode=bridge`, no `ExposedPorts`/`PortBindings`/`PublishAllPorts`, `Binds=[]`, `IpcMode=private`, restart `no`. Mounts are only the per-attempt volume `<name>-work` at `/aq/work` plus declared aliases. `NanoCpus`, `Memory`=`MemorySwap` and `PidsLimit` come from the reservation (`CreateRequest::resources`, now required). |
| Allowlist | `config.templates` | Exact `sha256:` digest mapped to a pinned `image@digest`; anything else is `InvalidRequest`. C3b owns the file format. `pull_template` pulls only allowlisted digests and proves presence by inspect. |
| Identity | `policy.rs` `labels` | `aq.managed-by`, `aq.backend`, `aq.node`, `aq.boot`, `aq.attempt`, `aq.template-digest`, `aq.hard-deadline-ms` and `aq.request-sha256` go on both the container and the volume. The container name is C1's deterministic node/attempt name. Replaying the same request is idempotent; a different request under the same name is `Conflict`. |
| Material | `tar.rs` `material_archive`, `deliver_private_material` | `PUT /containers/{id}/archive?path=/` of a ustar built in one pre-sized zeroizing buffer, with the directory at mode 0700 and the file at 0600. | Read-back | `read_file` (inherent) | `GET …/archive` capped at `max_read_bytes` plus 64 KiB for headers. Exactly one regular file is accepted; anything else fails closed. |
| Stop | `stop` | A never-started container is deleted, so only the volume remains. Otherwise `POST stop?t=grace`. The proof is a re-inspect showing `exited`/`dead` with `Running=false`. A container still running gives `Unconfirmed(StillRunning)`. |
| Preserve | `stop` result | The container is stopped and the volume kept. A volume-only entry inventories as `Stopped` with `disk_present=true`. |
| Destroy | `destroy` | Requires an authorization bound to this sandbox, then a confirmed stop, then `DELETE` of the container and the volume. Both must then `GET` as 404, otherwise `Unconfirmed(UnknownState)`. |

| Capabilities | `capabilities()` | `[PersistentDiskDuringAttempt]` only. `VmIsolation`, `NestedDocker` and `SuspendSnapshot` are refused at create as unsupported, never degraded. |

## Decision: rootless Podman (0005 §13)

The sandbox daemon is **rootless Podman 5.8.8** (`podman system service`), driven
through its Docker-compatible API (`api 1.44`). It is the upstream static
`podman-linux-amd64` release, signature-checked and unpacked under
`~/.local/opt/aq-sandbox-podman`. The reasons:

- It is daemonless per user. A dedicated API service runs with its own `HOME`,
  `XDG_CONFIG_HOME`, storage and socket, entirely separate from any Docker
  Desktop or host `dockerd` on the machine. That makes "never the host's main
  daemon" structural rather than configured.
- Rootless is its native mode and needs no root setup apart from cgroup
  delegation. Rootless Docker needs `dockerd-rootless-setuptool.sh`,
  `rootlesskit` and the same uidmap helpers.
- The worker code speaks only the Docker API, so a rootless `dockerd` remains a
  drop-in alternative. `connect` checks `name=rootless`, not the engine brand.

## Decision: confinement is `container` (0005 §8.3, §14)

The backend is **`container`-only**. Codex `native` (bubblewrap) is not
qualified inside docker-local sandboxes.
[confinement-probe.log](C2-evidence/confinement-probe.log) shows the result
under the fixed policy:

```
CapEff:	0000000000000000
NoNewPrivs:	1
Seccomp:	2
unshare -U true rc=0
unshare: write error: Operation not permitted
unshare -Ur id rc=1
```

Creating a nested user namespace is permitted. Mapping a UID inside it is
refused, and bubblewrap needs that mapping. Even if a later image or daemon
setting allowed the map, these sandboxes share the WSL2 kernel. **Shared-kernel
containers are not hostile-code isolation**, and this task claims none.
Re-evaluating `native` belongs with C6a, and needs a qualification run rather
than a policy change.

## Limitation: single-UID mapping (pending owner action)

This WSL2 host lists the user in `/etc/subuid` but lacks the setuid
`newuidmap`/`newgidmap` helpers (Ubuntu package `uidmap`). In that state Podman
refuses to start. Qualification therefore ran with `AQ_SANDBOX_SINGLE_UID=1`.
The script hides the subordinate ranges in a private mount namespace, so Podman
falls back to mapping exactly one UID. As a result:

- every process in every sandbox runs as the one host UID `1000`;
- the "Additional gid=10 is not present" warning in the probe comes from this
  mode;
- in-sandbox runner/agent user separation (`material_uid`/`material_gid` other
  than 0) is **unavailable**. Material is still 0600 inside its own sandbox,
  but it does not separate users within the sandbox.

The owner has been asked to install `uidmap` (`sudo apt install uidmap`). After
that, restart the service without `AQ_SANDBOX_SINGLE_UID`. No code change is
needed. The launch policy, limits and conformance results do not depend on the
UID range.

## WSL2 install notes

1. **Prerequisites.** WSL2 kernel ≥ 5.15 with the unified cgroup v2 hierarchy
   (`stat -fc %T /sys/fs/cgroup` → `cgroup2fs`). Install the
   `uidmap`, `slirp4netns` or `passt`, and `fuse-overlayfs` packages, or
   rely on the static bundle's helpers. Make sure `/etc/subuid` and `/etc/subgid`
   have a range for the user, e.g. `jkern:100000:65536`.
2. **Install.** Run
   `scripts/sandbox-daemon/aq-sandbox-podman.sh install podman-linux-amd64.tar.gz`
   with the upstream release, after checking its `.asc` signature. Everything
   goes under `AQ_SANDBOX_PREFIX` (default `~/.local/opt/aq-sandbox-podman`):
   binaries, a private `HOME` with `containers.conf`, `storage.conf` and
   `policy.json`, and graph storage. The user's own `~/.config/containers` is
   untouched.
3. **Socket path.** The socket is `$XDG_RUNTIME_DIR/aq-sandbox/podman.sock`
   (here `/run/user/1000/aq-sandbox/podman.sock`), mode `srw-------`, owned by
   the worker user. Configure `DockerLocalConfig::socket` with that path.
   `aq-sandbox-podman.sh socket` prints it. Never point it at
   `/var/run/docker.sock`; the backend refuses.
4. **Serve.** Run `aq-sandbox-podman.sh serve`, which wraps
   `podman system service --time=0 unix://…`. Use `podman <args>` to run the
   bundled CLI against the same private store, for example `podman pull` of an
   allowlisted digest.
5. **cgroup v2 delegation.** CPU, memory and PID limits only apply if systemd
   delegates those controllers to the user manager. Check with
   `cat /sys/fs/cgroup/user.slice/user-$(id -u).slice/user@$(id -u).service/cgroup.controllers`,
   which must list `cpu memory pids`. If it doesn't, create
   `/etc/systemd/system/user@.service.d/delegate.conf` containing
   `[Service]\nDelegate=cpu cpuset io memory pids`, then run
   `systemctl daemon-reload` and log in again. Without delegation Podman
   silently drops the limits. `live_launch_policy_applied` reads `cpu.max`,
   `memory.max` and `pids.max` inside the container to prove they took effect.
6. **Autostart caveats.** Autostart is out of scope here (E6a owns it):
   - The unit `aq-sandbox-podman.service` is shipped but not enabled.
   - A systemd user unit needs `[boot]\nsystemd=true` in `/etc/wsl.conf`.
   - The user manager only runs while a WSL session is open, unless
     `loginctl enable-linger $USER` is set.
   - WSL shuts the VM down after idle, which stops the daemon and the
     containers together.
   - Windows sleep or hibernate freezes the whole VM. The worker sees that as
     timeouts, which the backend reports as unknown inventory.
   - `KillMode=process` keeps conmon-managed containers alive across a daemon
     restart.
7. **Suspend/resume.** A paused or unreachable daemon is never read as
   "sandbox gone". `wsl_suspend_resume_reconciles_sandboxes` covers this with
   the scripted double. `live_wsl_suspend_resume_reconciles_sandboxes` covers
   it with SIGSTOP/SIGCONT on the real service PIDs.

## Deviations from the plan

- `policy::create_body` takes the validated `ResourceLimits` as a parameter
  instead of re-reading the `Option` from the request.
- `tar::material_archive` returns `Result`, so a material path outside a
  ustar-safe `/<dir>/<file>` shape is refused, not truncated.
- `pull_template` and `read_file` are inherent methods on `DockerLocalBackend`,
  not trait methods. C1's trait has no template-presence or read-back
  operation, and the conformance fixture only needs them through its adapter.
- `CreateRequest` gained `resources: Option<ResourceLimits>` and
  `mount_aliases: Vec<String>` (commit "add reservation limits and mount aliases
  to CreateRequest"). Duplicate aliases are rejected by the backend, not by
  `CreateRequest::validate`.

## Proposed design-doc changes (not edited here)

These go to docs task `calm-delta-18.2.1`. `aq-server/docs/architecture/*`
and `docs/specs/*` were not modified.

1. **0005 §13:** record "rootless Podman ≥ 5 via the Docker-compatible API on a
   dedicated per-user socket; rootless dockerd is an equivalent alternative;
   the backend checks `name=rootless`".
2. **0005 §5.1:**
   - Add that the reservation's CPU, memory and PID limits must be enforced
     through cgroup v2 user delegation, and that a host without delegation is
     not admissible. Podman otherwise drops limits silently.
   - Add that material delivery is a pre-start archive upload into a 0700/0600
     path outside the work volume and the aliases.
3. **0005 §8.3 / §14:** record the probe result above. In docker-local, the
   policy permits nested user namespace creation but refuses ID mapping, so
   `native` is not available and `container` stands.
4. **0005 (SBX10 / WSL2 notes):** document the single-UID fallback and its loss
   of in-sandbox user separation, and the `uidmap` prerequisite.
5. **C1 contract:** consider adding a template-presence check
   (`ensure_template`) to `PlacementBackend`, so B5a can preflight admission
   without backend-specific calls.
