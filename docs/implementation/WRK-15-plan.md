# WRK-15 staged observation implementation

The initial implementation is an independent pure `aq-observation` crate that consumes exactly lifecycle protocol0.1.0. No published lifecycle/session contract changes and no worker runtime journal migration are included in the first stage. Runtime bridging requires root review of schema, format choices and source fixtures.

1. Freeze the source-format capability matrix with immutable primary-source commit/file hashes. Synthetic fixtures remain labeled synthetic; current repository HEAD source does not qualify an installed or selected released CLI. The pinned v1 inventory provides Codex/Claude regression obligations, not four-harness product qualification.
2. Implement bounded incremental JSONL framing and explicit named formats, plus the bounded OpenCode public session DTO/export input. Normalize identity, source byte/record cursor, raw digest, parser artifact and observation time. Text/tool content stays out of usage facts; references do not invent retention receipts. No provider-home scanning or private database reads.
3. Persist normalizer state for native message/call identity, replay/correction references and cumulative source generations. Codex uses cumulative totals, ignores unchanged totals and marks mixed-model aggregate attribution unavailable without an unambiguous native reset. Claude/Gemini/OpenCode preserve observed native categories; missing categories are unknown, not zero. Native source costs without a provider receipt or rate-card provenance remain unknown. Conversation rewind does not undo already incurred usage.
4. Add the independent bounded journal/outbox: one atomic commit covers consumed cursor, parser state and outgoing facts. Exact batches survive unknown acknowledgments. Ordinary capacity cannot consume the reserved gap/health allowance; overload either holds the cursor or advances only with an explicit scoped loss gap under policy. No shared worker authority lock or network exchange is held by this store. Source path/handle checks refuse redirects, changed identities and unrelated sessions.
5. Qualify fixtures for four formats, partial/oversized/malformed records, rotation/truncation, replay/history, cumulative reset, mixed models, correction/mutation semantics and explicit unavailable categories. Fault tests cover cursor/facts atomicity, restart, lost batch receipts, finite overflow and independent control calls. Package qualification must require no sibling runtime checkout.
6. After review, integrate only through an explicitly versioned worker runtime seam. Actual harness-version/native accounting qualification, authenticated central delivery, ledger reconciliation and INT-03 remain distinct required evidence. Keep WRK-15 open until its full accepted scope is complete.

The machine-readable [format matrix](WRK-15-source-formats.json) is the source inventory. Gemini's selected source is append-only JSONL with metadata, full message updates, `$set`, `$patch` and `$rewindTo`; unsupported mutation fields produce an explicit gap rather than silently inventing usage. OpenCode is scoped public export/session-message DTO input, not direct SQLite access. Closed Claude native-format qualification remains pending beyond v1-backed synthetic fixtures.
