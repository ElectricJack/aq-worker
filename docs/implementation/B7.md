# B7 — Scoped AQ access for agents inside sandboxes

Task: `noble-summit-37.10`. Plan: commit `302992c` (`docs/superpowers/plans/2026-11-04-B7-scoped-agent-access.md`). Implementation and evidence: one squashed commit, the one containing this document. The exact published OID is recorded in the AQ task close.

## Decision: who issues

The node issues the agent credential. It calls `/v2/worker/agent-session` through the existing `NodeClient` and `Allocator` (`aq_agent_client::provision`), then hands the session files to the runner. The runner never calls issuance. Its job is to install the delivered files for the agent and to stop provisioning when the attempt ends.

The server stays authoritative. Expiry, revocation and permit checks happen on every request it serves. This decision is also recorded as a task comment. No aq-server follow-up is needed.

## Delivered

### Installation inside the sandbox (`crates/aq-agent-client/src/provision.rs`)

- **Types:**
  - `SessionDelivery { client, context, credential }` holds the raw bytes. Its `Debug` impl prints only `<redacted>`.
  - `Allocator::delivery(session)` reads the node's ready directory.
- **`install_delivered(state_dir, delivery, endpoint, not_after_ms, now_ms)` (lines 136–197).** Nothing is written until every check below has passed:
  - The client config must be `format_version` 1, and its binding must be valid.
  - `edge_authentication` must be `false`, so sandbox delivery never carries Access egress credentials, and `agent-egress.json` is never installed.
  - The startup bundle must parse and validate. Its binding must equal the client binding, and its `graph_context` must equal the credential's context.
  - The credential document must be at most `MAX_DOCUMENT_BYTES` and must pass `Context::new`, which checks the binding, the profile digest and the context digest.
  - **Expiry:** `credential.expires_at` must be later than `now`; otherwise the delivery is refused as "already expired". It must also be no later than `not_after_ms`; otherwise it is refused because it "outlives the attempt grant". Expiry is refused, never silently clamped.
  - **Endpoint:** `server_url` is rewritten to `endpoint`, which is the B6b loopback AQ proxy origin. The agent therefore never holds, or needs, the Access token.
- **Write order:** files go into a fresh 0700 `PrivateDir`, in the order `context.json`, `client.json`, `credential.json`.
- **`revoke_delivered(state_dir)` (line 199)** removes `credential.json` using the new `PrivateDir::remove` (`files.rs`). It succeeds if the directory is already gone.

### Worker guard (`crates/aq-worker/src/native/runner/sandbox/agent_access.rs`)

- **`AgentGrant::from_runner(&RunnerHttp)`:**
  - `not_after_ms` is `min(grant_expires_at_ms, hard_deadline_ms)`, taken from the delegated permit context.
  - `live` is `!authority_lost()`.
- **`AgentAccess::provision(delivery, grant, now_ms)`** refuses when any of these holds:
  - the guard has been stopped;
  - the grant is not live;
  - `now_ms >= not_after_ms`;
  - the delivered binding names another attempt or another node.

  The binding check runs before anything is written. Only then does it call `install_delivered` with the proxy origin and the grant bound. If `stop()` races with an install, the install is revoked and refused.
- **`AgentAccess::stop()`** sets a stopped flag that is never cleared and removes the credential. Callers use it on cancellation, expiry or revocation. Calling it twice is fine.

### aq-agent commands (`crates/aq-agent-client/src/{client,main}.rs`)

`context`, `graph get|revision|history|search|context|relationships|command` and `operation get` already existed. B7 adds:

- **`message inbox [--task] [--after N] [--limit N] [--thread UUID]`** and **`message send|ack|body --request-file F`**, implemented by `AgentClient::message` (`client.rs:456`).
- **Schema checks:** each request and response is validated against the vendored aq-agent-api 0.1.0 schemas.
- **Mailbox scope:** an inbox or send recipient must be the bound task mailbox or the bound session mailbox. Anything else is refused before any request is sent.

### Runtime bundle

- **Build:** `Dockerfile.runtime` builds `-p aq-agent-client --bin aq-agent` and copies the binary to `/opt/aq/bin/aq-agent`.
- **Build-time checks:** the image runs `aq-agent --version` and fails if `/opt/aq/bin/aq` exists.
- **Manifest:** `bundle_manifest.py` lists an `agent_client` artifact (`aq-agent`, version taken from `crates/aq-agent-client/Cargo.toml` through `scripts/package-sandbox.py`'s `source.json`).
- **README:** `packaging/sandbox/README.md` now says the bundle ships `aq-agent` and never `aq`.

## Limits

- **Installation identity.** `PrivateDir` requires the directory to be owned by the effective uid and to have mode 0700. Production installation must therefore run as the sandbox agent user (`run_as_agent`), not as the runner user.
- **Not wired into launch.** The node→runner transport for `SessionDelivery` and the call to `AgentAccess::provision` and `stop()` from the production `sandbox-run` launch and cancellation paths are library APIs with tests, not wired in. This is the same B2 codec blocker recorded in B6a2 and B6c.
- **In-process client.** The versioned-mutation test drives the `AgentClient` library, which is the same code the `aq-agent` binary runs, rather than the binary itself. `CARGO_BIN_EXE_aq-agent` is not available to another package's tests. The existing `aq-agent-client` CLI tests cover the CLI layer, including exit codes.
- **Not directly tested.** `AgentGrant::from_runner` is a two-field mapping from `RunnerHttp::context()` and has no direct test. `message send` and `message ack` are not journaled for replay; `delivery_unknown` belongs to F3.
- **Out of scope, per task:**
  - mailbox poll/ack harness delivery;
  - `message reply`;
  - waits (H4);
  - supervisor credentials (F1b);
  - base bundle build (C3a);
  - proxy changes (B6b);
  - server permit enforcement (B2).
