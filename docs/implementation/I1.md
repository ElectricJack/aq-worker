# I1 — Claude Code adapter qualification

Task: `azure-horizon-22.4`. Plan: `docs/superpowers/plans/2026-11-04-I1-claude-adapter.md`. The plan, the implementation and this evidence are in one squashed commit, the one containing this document. The AQ task close records the exact published OID.

**Result in one line.** Claude Code 2.1.318 runs the real C6a recipe in a docker-local sandbox on the owner's subscription login. The recipe now writes the native session transcript, and both Claude transcript readers are qualified against a real 2.1.318 session. **Not delivered:** the API-key path and an enrollment capture flow, both set aside by owner decisions (see [Owner decisions and unmet acceptance](#owner-decisions-and-unmet-acceptance)).

## Delivered

### Recipe writes the native transcript (`crates/aq-worker/src/native/adapter/claude.rs`)

- **`ClaudePaths.session: Uuid` (line 55).** The attempt chooses the native session id. The recipe passes `--session-id <uuid>` (line 177) in place of `--no-session-persistence`, so the CLI persists the session under the attempt's identifier.
- **`ClaudeRecipe.transcript` (line 67)** is the exact path the pinned CLI writes: `<private_home>/projects/<slug>/<session>.jsonl` (lines 128-150).
  - The slug is the workspace path with every non-alphanumeric byte replaced by `-`. This was witnessed on 2.1.318: workspace `/aq/work/repo` gives `projects/-aq-work-repo/<uuid>.jsonl` (`I1-evidence/run-2/home-files.txt`).
  - A slug over 200 bytes is refused (`MAX_PROJECT_SLUG`, line 72). Longer paths are shortened with a hash that the recipe does not reproduce, so they get no guessed path.
- **The private home is wiped with the sandbox.** `cleanupPeriodDays: 1` stays in the settings, so a reused home would still be swept.
- **`ClaudeAgentHome::plan` (`runner/sandbox/harness_config.rs:108`)** returns the recipe without touching the filesystem. It is used for a home that lives inside the sandbox. `install` is `plan` plus the private settings write.
- **Callers** `native_probe.rs` and `tests/sandbox_security.rs` pass a fresh session id.

### Readers skip 2.1.318 metadata (`crates/aq-observation/src/formats/claude.rs:13-40`, engine copy byte-identical)

- **Before this change**, every 2.1.318 metadata record became an `UnsupportedFormat` gap, which means the session was not observable. The reader now skips the witnessed kinds:
  - headless: `atis-latch`, `api-request-shape`, `api-request-blob`, `api-request`, `tools-used`, `last-prompt`, `cost-state`;
  - interactive UI state: `mode`, `permission-mode`, `session-owner`, `ai-title`, `pr-link`, `file-history-snapshot`, `file-history-delta`.

  These kinds sit beside the existing `summary`, `queue-operation` and `attachment` kinds.
- **Usage and tools stay on the assistant rows.** The per-call facts that `api-request*` and `cost-state` summarize are read from the assistant rows, which carry `message.id` and `usage`.
- **`system` and unknown kinds stay explicit gaps.** `system` includes the context-loss record `compact_boundary`.
- **Artifacts regenerated** with `cargo run -p aq-observation --example export` and `-p aq-observation-engine --example export`:
  - the parser digest in `capabilities.json` and `normalized-golden.json`;
  - the Claude row in `source-formats.json`, with its qualification scope and fixture provenance;
  - the `docs/implementation/WRK-15-source-formats.json` mirror.

### Real-session fixture and qualification test

- **Fixture: `crates/aq-worker/tests/fixtures/claude-real-2.1.318.jsonl`** (3371 bytes, sha256 `733179315b375006b77fdae332e31038f0fe97a52e65533cabf3ac7afa815967`).
  - It is the live run-2 session sanitized by `I1-evidence/sanitize.py`; provenance is in `I1-evidence/provenance.json`.
  - **Kept:** record order and kinds, the attachment subtype, tool names, model, `stop_reason` and numeric usage counters.
  - **Replaced:** ids are replaced with stable placeholders; text, tool input, tool results and thinking are replaced or emptied.
  - **Not kept:** cwd, git branch, timestamps and request bodies. The test asserts their absence.
- **Test: `claude_real_session_2_1_318_qualifies_reference_and_durable_engine` (`runner/sandbox/observations_tests.rs:542`).** It runs the fixture through the reference normalizer and through the durable engine collector, and asserts all of the following:
  - no gap;
  - three per-call usages with the native counters `(2,63,17482,1564)`, `(2,116,19046,199)` and `(2,102,19245,188)`;
  - a `ToolStarted` and a `ToolResult` for `Read` and for `Edit`;
  - exactly one `TurnBoundary { in_turn: false }`;
  - the engine batch equals the reference: each usage's call, basis, counters and completeness, and the cursors.
- **RED:** the same test against the HEAD reader fails on the `unsupported-claude` gaps (`I1-evidence/red-mutation.log`).

### Live test runs the real recipe (`crates/aq-worker/tests/claude_live.rs`)

- **The runner is the C6a recipe.** The test plans the container-mode recipe through `authorize` and `ClaudeAgentHome::plan`, using in-container paths. It renders the recipe's settings, env and POSIX-quoted argv into the runner script, replacing the earlier hand-written flags.
  - The prompt arrives on stdin, never through argv or the shell.
  - The token comes from the leased private material and reaches Claude only as `CLAUDE_CODE_OAUTH_TOKEN` in the spawned env. The file is deleted before work starts, as in I4a.
- **It checks the transcript.** It asserts the native transcript exists at exactly `recipe.transcript`, then runs the reference normalizer over it (`normalize`, line 236). It also asserts:
  - usage is present;
  - the Edit tool was started and returned a result;
  - a turn boundary was reached;
  - no gap other than the frame-bound gaps below.
- **Frame-bound gaps.** 2.1.318 writes `attachment` records of subtype `prompt_snapshot` (79 KB and up, mostly tool schemas) mid-turn. These exceed the 64 KiB frame bound (`aq-observation/src/framing.rs:5`) and arrive as explicit `Gap{Malformed}` facts, not as skipped records.
  - The test counts them separately and prints `frame-bound gaps: N`. Run-2 had 2.
  - The Claude reader keeps no state that such a gap resets, so the usage and tool facts around them survive. The test asserts this.
- **Offline guards** (`claude_live.rs:330`):
  - the prompt is not in argv;
  - the recipe never sets `IS_SANDBOX`;
  - no `FORBIDDEN_ENVIRONMENT` variable appears.

The refresh mechanism is undocumented, and an expired token cannot be refreshed by Claude Code. With only the env token, no `.credentials.json` is written (witnessed: `credentials_file false`). | https://code.claude.com/docs/en/authentication |

AQ forbids every non-subscription variable (`FORBIDDEN_ENVIRONMENT`) and sets `forceLoginMethod: "claudeai"`. | https://code.claude.com/docs/en/authentication, https://code.claude.com/docs/en/env-vars, https://code.claude.com/docs/en/headless |
| API key through a loopback proxy | Documented gateway shape: `ANTHROPIC_BASE_URL`, `POST /v1/messages` (`/v1/messages/count_tokens` optional), forwarding `anthropic-version` and `anthropic-beta` verbatim, and model discovery with `GET /v1/models?limit=1000`. ## Limits

- **Frame-bound `prompt_snapshot` attachments.** The 2.1.318 attachments above 64 KiB become explicit `Malformed` gaps rather than skipped metadata. Facts survive with the Claude reader, but a consumer that treats every gap as loss will over-report. The sanitized fixture does not reproduce them. Follow-up: a prefix-aware skip for `"attachment":{"type":"prompt_snapshot"`, or a per-format frame bound.
- **The fixture scope is one session.** It covers 32 records, the Read/Edit tool cycles, three calls and one turn. Compaction (`system`/`compact_boundary`), subagents, thinking-heavy turns and multi-turn sessions are not qualified.
- **The slug rule is witnessed, not documented.** If the transcript is missing, the live test fails; production should treat a missing transcript as an observation gap, not as silence.
- **`native` confinement is not qualified** on any host. Claude's sandbox is fail-open unless `failIfUnavailable` is set, and the recipe's `native` settings do not yet set it (follow-up).
