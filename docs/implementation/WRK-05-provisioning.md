# WRK-05 provisioning and recovery component evidence (draft)

This is component evidence for the uncommitted client candidate, not WRK-05 completion or a publication claim. Full client/CLI review, clean source pinning, packaging and standalone qualification are owned by the root task.

`Allocator` retains a per-node private allocation journal and immutable session/attempt binding. Each allocated session reserves at least64 MiB, covering atomic operation-journal/context replacements plus protected credential/configuration overhead, with a separate2 MiB node-journal reservation. Admission bounds retained count, configured total reservation and available filesystem headroom. Allocations and unknown intents are never silently reclaimed. Unexpected private files, orphan temporaries, symlinks, hardlinks or permissive files refuse further provisioning; they are retained for explicit recovery.

A tokenless StartupContext and exact issuance binding/version intent are durable before HTTP. The node marks the intent Unknown before exchanging a request. A lost or invalid response cannot automatically replay plaintext issuance. Local recovery can complete an already retained exact-version response without network; explicit new recovery intent must name the original or immediately next CAS version after Unknown (or the installed version for an ordinary refresh), and the real daemon issuance endpoint remains the live authority/version fence. Issued context is validated against the exact ProfiledOffer, API Binding, profile/context digests and returned credential version. Only then are private credential/context files installed and client.json published. Refresh atomically replaces the credential file; an agent operation journal may stay open. Node and machine authentication never enter agent files, and dedicated agent egress credentials must differ from node egress credentials.

Twelve provisioning tests cover real synthetic issuance, private file modes, missing initial publication, preserved allocation quota across reopen, unknown reply/no duplicate HTTP, before-commit same-version recovery and after-commit next-version rotation with a real CAS refusal, changed intent/startup bytes, wrong returned binding, retained-response crash-prefix recovery, atomic refresh, symlink/permissions/orphan refusal, owner lock, physical headroom and the distinct8 MiB context versus1 MiB wire bound. Tokenless allocation invents no credential; opaque credentials come only from the authenticated issuance response.

Five node-recovery tests cover known-ID lookup, bounded centrally paginated lists and one retained-ID retry with node authentication. They prove no issuance route, new mutation payload, session credential or grant is created. Response checks bind request/attempt/operation identity and confirmed workspace receipt, enforce unique IDs/page limits, and reject lookup pagination. Foreign bindings, IDs, workspaces, wrong status, malformed responses and new payloads refuse. These finite peers do not replace live daemon auth/DB qualification.

No provider key material, provider lease, execution grant, launch, task completion, retention deletion authorization or universal AQ tool surface is implemented by these components. Message client methods remain outside the current client. The allocator intentionally retains full slots until a later explicit retention/recovery protocol allows reclamation.
