This bounded source increment preserves worker0.4.0/FORMAT11 and the schema1 NativeConfig JSON. The negotiation object continues to contain exactly contract and features. A strict neutral envelope rejects duplicate and unknown fields, compares the complete contract ArtifactRef to the two frozen supported artifacts, and only then decodes the corresponding nominal feature enum. Existing configuration selects the frozen profile exactly; no default, fallback, automatic upgrade, old/new DTO casting, or authority interpretation is added.

The runner retains a closed ConfiguredPreparation value. Its two branches instantiate the existing collection algorithm with the corresponding actual typed options and InputPipeline methods. Both return the existing opaque DurablePhaseExecution. Collection and final completion are checked against the explicit configured profile.

A small private TerminalProfile helper selects only an exact retained execution/Started branch and validates its matching historical terminal context. It delegates to existing nominal Started/Stopped receipt owners, preserving their actual validation and durable ACK writes. It is history-only data; it cannot construct a host, restore a grant, or activate a runtime. Adapter's separately owned drive_running captures it only after the existing owner-checked output attachment. Final completion requires the configured matching Started and Stopped ACK pair.

Owned files are native/runner.rs, runner/config.rs, runner/prepare.rs, new runner/profile.rs and their focused tests. Adapter owns runner/codex.rs and the named-readonly production factory. This dispatch does not activate an executor by itself. Adapter’s independently reviewed join adds an explicitly selected trusted-node named-readonly tag; the old sealed-memfd tag remains refused. No daemon framework, SQL, disk-format, component-version, provider or process changes occur in this increment.

Checks cover frozen configuration compatibility, strict duplicate/unknown/contract/feature refusal, explicit refresh selection, both actual typed collection paths, retained-profile and mixed-context refusal, matching completion, and affected strict checks. Actual process/provider qualification remains a separate gate.
