# Explicit registry-refresh adoption

Worker 0.4.0 creates FORMAT11 journal roots. Opening FORMAT10 refuses before decoding current state or touching a pending write; preserve that root for its original worker binary’s inspection and safety recovery. There is no migration or live-authority reconstruction.

The frozen preparation-v2 path remains a distinct typed instantiation. The new `preparation_refresh_v1` client uses exactly negotiated admission 0.1.10 and terminal 0.1.1 artifacts. Same HTTP paths and family numbers do not select a profile: full contract/runtime/qualification identity must match the server policy. No automatic negotiation upgrade is allowed.

`phase_*` and `refresh_*` histories are mutually exclusive per attempt. Shared physical download/source/material algorithms capture `InputOrigin::Phase` or `Refresh`; neither can be read as the other. The transport acceptance itself remains the actual common immutable acceptance. Original clocks, four registry references, request/delivery bytes and digests stay in their actual profile types.

`PreparedRefreshInputs` owns actual verified startup/artifacts/workspace/materials. A private Frozen/Refresh enum retains these process-local owners behind the existing `DurablePhaseExecution` and local host APIs; it is not a wire conversion or a serializable permission. Shared attempt/inline/startup limits span legacy and both typed phase profiles. The opaque network observation is retained before fsync, and the actual input owners are retained synchronously before awaiting network or storage. Reopen is history only.

Physical host validation reads a borrowed projection of the genuine typed grant/lease and checks the exact record digest, owner, deadlines and kernel. Running and stopped publications select the actual matching terminal context and retain typed ACKs; the single reserved host-history budget covers either profile. No old/new DTO serialization conversion or permissive schema fallback exists.

This source increment does not implement continuation parking. A later concrete history insertion requires an explicit disk-format decision; no placeholder authority fields are added to FORMAT11. It does not enable a production profile, call a provider, or change any daemon/worker configuration. Runner owns explicit server policy and actual static process qualification with the actual 0.4.0 binary/source pins.

Qualification gates: old actual phase HTTP/journal/physical-input tests; refresh proposal/Accepted/Prepared/terminal transport and durable-history tests; cross-profile and lost-response/reopen refusals; FORMAT10 byte-preserving refusal; combined resource bounds; exact frozen dependency payload verification; offline locked metadata and affected strict checks.
