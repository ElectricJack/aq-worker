# Spec 0006 phase 3b and phase 6: `aq` in the sandbox, and the live proof

Spec: aq-server `docs/specs/0006-agent-channel.md`, §9 step 3 (ship `aq`), §10 phase 6 and §11 (the live proof). Branch `chan/worker-aq-cli`. Evidence is in [`0006-P6-evidence/`](0006-P6-evidence/).

## Phase 3b: `aq` in the runtime bundle

- **Pin.** `packaging/sandbox/pins.json` input `aqv2`: aq-server's static `aqv2`, version 0.1.0.
  - aq-server commit `e058e7d75ec6d2c23ac90418edd62cea69bdde06`.
  - SHA-256 `eef04c9850b69a2795af3edf0ebebd25356fa7e52d46caab0821e027e908b3c3`, 5,343,496 bytes, `static-pie linked`.
- **Build.** No release asset exists yet. [`packaging/sandbox/build-aqv2.sh`](../../packaging/sandbox/build-aqv2.sh) builds the CLI the way aq-server's CI `musl` job does:
  - `git archive` of the pinned commit;
  - inside the pinned builder (`rust:1.96.1-bookworm@sha256:a339…`), with `musl-tools` and a private target directory: `CC_x86_64_unknown_linux_musl=musl-gcc cargo build --release --locked -p aqv2 --target x86_64-unknown-linux-musl`;
  - the script refuses any digest that differs from the pin. Two clean builds gave the same digest.
- **Install** (`Dockerfile.runtime`). The binary goes in as `install -o root -g root -m 0755 aqv2 /opt/aq/bin/aq`. `/opt/aq/bin/aq-agent` becomes the deprecated wrapper `exec /opt/aq/bin/aq "$@"`, kept for one template generation. The bundle no longer builds `aq-agent-client`.
- **B7 check inverted.** The bundle build now requires all of:
  - `/opt/aq/bin/aq` is `755 0 0`;
  - `aq --version` equals `aq <pinned version>`;
  - `aq --help` and `aq-agent --help` print `Usage: aq`.

  `test ! -e /opt/aq/bin/aq` is gone, and the runtime-bundle test asserts that it never comes back.
- **Manifest.** `manifest.json` lists `agent_client` (`aq`, `/opt/aq/bin/aq`, the pin's version, sha256, bytes) and `agent_client_wrapper` (`aq-agent`).
- **Real bundle build.** [`bundle/`](0006-P6-evidence/bundle/) holds the build of HEAD with the pinned public inputs (image `sha256:fa572acb…`). Every check above passed (`bundle-checks.log`). The installed `/opt/aq/bin/aq` has the pinned digest, and the generated `manifest.json` lists it.
- **Pre-existing build break, fixed.** `scripts/package-sandbox.py` did not export `packaging/sandbox/boat_materialize.py`, which `crates/aq-worker/src/template.rs` embeds. The runtime bundle build therefore failed on main in `cargo build` ("couldn't read …/boat_materialize.py").

### `AQ_CHANNEL` and `aq` reach Claude Code's Bash tool

- **How the env reaches the Bash tool.** The launch builds the agent's environment in `sandbox_driver::input_entries`: the C6a recipe environment, with `/opt/aq/bin` prefixed to `PATH`, plus `AQ_CHANNEL=unix:/aq/channel/aq.sock`, written to `/aq/in/env`. The fixed runner exports each line of that file and execs `claude`, and Claude Code's Bash tool inherits the process environment. No other environment is involved.
- **Proof in the live attempt.** In both live attempts the agent's first Bash call printed `AQ_CHANNEL=unix:/aq/channel/aq.sock`, `PATH=/opt/aq/bin:/usr/local/bin:/usr/bin:/bin`, `/opt/aq/bin/aq` and `aq 0.1.0` (`run2/transcript.md`, step 0).
- **Proof before the stack runs.** [`precheck/`](0006-P6-evidence/precheck/) shows the same result from one real Claude call in the template, using the runner's exact env file.

### Socket owner and mode

- **The socket the agent sees.** Seen from inside the live sandbox, the mounted directory is `drwx--x--x 0 0 /aq/channel` and the socket is `srw-rw-rw- 0 0 aq.sock`.
- **Single-UID daemon (this desktop).** The desktop's rootless Podman sandbox daemon runs in single-UID mode (`AQ_SANDBOX_SINGLE_UID=1`). The agent is in-container uid 0, which is host uid 1000 and the socket's owner, so the CLI's `stat` and `connect` succeed (`run2/transcript.md`).
- **Mapped agent uid (the VPS case).** With a uid mapping, the agent is "other" relative to the socket owner. [`socket-uid/`](0006-P6-evidence/socket-uid/) runs the static `aq` as uid 10002 against a host socket created exactly as `AgentChannel` creates it (directory 0711, socket 0666, owned by host uid 1000):
  - `stat` works through the 0711 directory;
  - `connect` reaches the server, and the stub's reply is read;
  - listing the directory is refused, as intended.

  This host cannot start a second rootless Podman with subuids (`newuidmap` is not installed), so the mapped case was run under Docker as a non-root uid. The permission check is the same.

### Query strings through the proxy

`aq commands --all` sends `GET /api/v1/commands?all=true` through the channel. The agent got the full "not runnable" section, which the server produces only for `?all=true` (`run2/transcript.md`, step 1). The proxy forwards the whole request target. It logs only the path (`channel-proxy.log`: `method=GET path=/api/v1/commands`). #43 does not drop query strings.

### Server bugs found and fixed

- **aq-server #108** (`fix/agent-task-children`):
  - Migration 0099 adds an agent journal principal domain.
  - A §6.8 refusal replaces the bare 403 for a parent outside the project.
  - `parent-child` edges are readable within the `task.read` scope.
  - A 401 on the command surface now means only "credential rejected": the new `unsupported_api_version` is 426, and agent access not configured is 503.
- **aq-server #109** (`fix/revoke-on-stop`): a normal stop revokes the agent credential in the stop transaction.
