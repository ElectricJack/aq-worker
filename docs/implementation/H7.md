## Implemented path

`native/terminal_output.rs` owns one epoch's `aq-terminal-renderer` 0.1.0 state and bounded literal replay. Each frame reaches `Renderer::bytes` before replay eviction. Ordered resizes carry the exact preceding output watermark; unknown layout changes, observer discontinuity and unsupported parser input invalidate snapshot completeness. Only a verified pre-output blank baseline admits a complete physical image. A fresh epoch constructs a fresh renderer and starts at output sequence zero.

Snapshot capture and frame ingestion share the output owner's lock. `Snapshot.state` contains the opaque AQRI StateImage, its digest, terminal identity, geometry and exact `through_sequence`. Restore checks the image identity, digest, watermark and geometry. A pending upload retains immutable snapshot/frame/gap bytes and operation IDs across failures and cancellation. New bytes continue into the renderer and bounded replay while HTTP is blocked. After eviction, a new cut supersedes missing replay; later frames begin strictly after its watermark. No agent restart is needed.

The native live-host relay joins its persisted verified baseline to the actual running host before constructing the renderer. It consumes the original control observer for every profile. Reconnect requests an image rather than opening a disposable PTY redraw client. Both native and synthetic startup retain bounded bootstrap output until that same owner begins draining. If the diagnostic drain has already consumed output, later adoption of a complete blank baseline is refused.

The relay's existing opaque Snapshot wire and replay accept StateImages without a protocol change. The bridge HTTP output lane now admits snapshots; control receipts remain on the control lane. The transport fixture covers maximum-size, high-byte opaque state, and the worker tests restore real renderer images through the pinned relay replay implementation.

The observed sandbox entrypoint is `sandbox::run(..., SandboxStartup::observed(&startup, &qualified_adapter, channels), ...)`; `run_as_agent` accepts the same input. It validates the exact frozen manifest and shared permit authority before preflight or journal creation. The host prepares a closed launch gate, opens the original observer, verifies and durably records its blank baseline, installs the renderer, and only then releases startup. Separate scoped tasks drain that observer, upload output and run B6c's watch poll. Shutdown aborts held output/poll futures without waiting on their transport. Watch identity and supported effects are checked before committing the poll cursor.

`SandboxChannels::open_output` accepts a `VerifiedBlankBaseline` and installs one `SandboxOutput`. Its producer, 50 ms upload loop and observer drain are independent of renewal and cancellation. Upload uses its own connection pool and one pending exchange, never holding the replay or guardian lock across HTTP. Authority-loss state remains shared with the permit client. A reconnect requests a fresh cut without replacing the observer.

## Bounds

- Frames are at most 64 KiB. Local framing uses at most 60 KiB to leave room for worst-case JSON expansion in a 256 KiB tail exchange.
- One snapshot exchange is at most 1 MiB encoded; the protocol StateImage bound remains 192 KiB. A pending exchange and replay are independently bounded.
- Replay reserves at most 1 MiB/session and 32 MiB/node before native attachment. Tail frame and gap counts retain the existing bounded implementation.
- Output uses token buckets of 256 KiB/s/session and 2 MiB/s/process node, with one second of burst capacity. Frames and image payload bytes are charged, including retries. Across separate sandbox processes, the authoritative server applies the node aggregate (`terminal/runtime.rs`, `Rate::new(2097152, ...)` and per-session `262144`).
- At most four viewers/session; native metadata also checks the node subscription limit. Sandbox polls retain B6c's one-poll cursor lock, 20 s maximum hold and no idle I/O.
- Observer drain targets 10 ms; upload flush targets 50 ms when capacity and transport are available. This task does not measure physical latency.

## Review and decisions

A fresh read-only whole-branch review (gpt-6-astra, `44fe1a5..7f1f318`) found three Important defects. Each received a regression that failed before its fix; all three then passed (`cargo test --locked -p aq-worker --lib h7_review`, logs `.aq/tmp/H7-review-{red,green}.log`):

- Upload batching now emits an ordered prefix of leading gaps followed by frames before the next gap. Renderer-gap frames never overlap an uploaded gap or precede the peer's high watermark. The regression applies batches to pinned Replay in actual server order.
- Acknowledging a blank snapshot at sequence zero leaves the next unchanged flush idle. Explicit reconnect demand still requests a snapshot.
- Transient Watch errors retry with 50 ms cancellation-aware backoff and unchanged cursor; authority loss ends polling. A fixture fails a poll, accepts a Watch at the same cursor and subscription count, and holds the next poll until runtime stop.

No review minors were deferred. Review exclusions match the limits above. Implementation rulings were: execute inline under the held task's authorization (cost if wrong: plan revision); use Cargo because local `aq test` runs pytest (cost: no Python semaphore); admit existing opaque snapshots only on the bridge output lane (cost: transport compatibility must remain covered); retain the original native observer rather than redraw clients (cost: observer failure invalidates completeness); use package-scoped formatting for the existing vendored workspace issue (cost: unrelated package formatting remains unchecked); preserve old fixture startup syntax while adding explicit observed startup (cost: production callers must migrate explicitly). Final review retained the task's exclusions for physical qualification/latency, B2 CLI codec, other CLIs/browser, server aggregate admission, and full-suite qualification; their costs are the corresponding unqualified deployment, external prerequisite, external rendering, server dependency and unrelated regression coverage limits.
