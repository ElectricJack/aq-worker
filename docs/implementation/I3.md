| Row | OpenCode 1.18.35 |
| --- | --- |
| Headless invocation | `opencode run --format json --pure --model <provider>/<model>`. The prompt is on stdin, read when stdin is not a TTY. Events (`step_start`, `tool_use`, `text`, `step_finish`) are JSON lines on stdout. The docs call `run` the "non-interactive mode … for scripting, automation" and `--format json` the "raw JSON events" format. `--pure` disables external plugins. `opencode export <session>` writes the session as JSON, which is the reader input. |
| Config directory variable | `OPENCODE_CONFIG` names the config file; the docs also list `OPENCODE_CONFIG_DIR` and `OPENCODE_CONFIG_CONTENT`. The adapter sets only `OPENCODE_CONFIG`, inside the private home, and refuses the other two. `OPENCODE_DISABLE_PROJECT_CONFIG=1` and `OPENCODE_DISABLE_AUTOUPDATE=1` are documented. The adapter also sets the following, which the binary reads: `OPENCODE_DISABLE_MODELS_FETCH`, `_LSP_DOWNLOAD`, `_SHARE`, `_CLAUDE_CODE` and `_EXTERNAL_SKILLS`, plus `_DEFAULT_PLUGINS` on the proxy route. `HOME` and every `XDG_*` directory sit inside the private 0700 home. |
| Credential file and refresh | `~/.local/share/opencode/auth.json`, which is `$XDG_DATA_HOME/opencode/auth.json`, written by `opencode auth login`. Entries take two shapes: `{type:"oauth",refresh,access,expires,accountId?}` or `{type:"api",key}`. The OpenAI "ChatGPT Pro/Plus (headless)" method is a device-code login. OpenCode refreshes the OAuth entry in place in `auth.json`, and the C6b write-back keys on `openai.expires` advancing. |
| API-key routing through a loopback proxy | Per-provider `provider.<id>.options.baseURL` (documented "for proxies or custom endpoints"). The proxy route points `openai` at `http://127.0.0.1:<port>/v1`, and `auth.json` holds only the proxy's attempt-local capability as an `api` key. The AI SDK sends typeless "easy input messages" (`{role, content}`), so the B6b policy now admits exactly that shape as a `message` (`aq-responses-transport` `items.rs`, test `typeless_easy_input_message_is_a_message_and_nothing_else_is`). Not run live (owner: no API keys). |
| Native sandbox | None. The docs describe only approval-based permission rules (`allow`/`ask`/`deny`, `*`, `external_directory`, `question`, `webfetch`) and no OS isolation. Only `container` confinement is qualified; `native` is refused. The adapter allows every tool without prompting, except `external_directory`, `question`, `webfetch` and `websearch`, which are `deny`. |

## Delivered

- **Readers.** `crates/aq-observation/src/formats/opencode.rs` and `crates/aq-observation-engine/src/formats/opencode.rs` accept 1.18.35's `{info, parts}` records, which `opencode export` produces. They are tested against a real 1.18.35 session fixture (`tests/fixtures/opencode-1.18.35-session.json`). In 1.18.35 the v2 `Session.Message` DTO is empty for `opencode run` sessions.
- **Adapter.** `crates/aq-worker/src/native/adapter/opencode.rs` is a pure recipe with:
  - the pinned `OPENCODE_CLI_VERSION = 1.18.35`;
  - direct argv and an env allowlist;
  - `FORBIDDEN_ENVIRONMENT`, which refuses inline config, auth content, permissions and API-key variables;
  - `opencode.json` bytes with one enabled provider, title generation and auto-compaction off, `share` disabled, no snapshot and no prompts;
  - the output cap from `ModelSettings` and reasoning effort on the `openai` routes;
  - `container` confinement only.

  Unit tests are in `adapter/opencode/tests.rs`.
- **Private home.** `harness_config.rs::OpenCodeAgentHome` creates a 0700 home holding `opencode.json`. The proxy route also writes a 0600 `auth.json` holding the capability; the Ollama route writes none.
- **Subscription.** `subscription_login.rs` has `LoginKind::OpenCodeChatgptAuth` (wire name `opencode_chatgpt_auth`). It installs the login into a fresh private `$XDG_DATA_HOME/opencode`, validates it with `validate_chatgpt_auth_json`, writes it back when `openai.expires` advances, and wipes it. Tests are in `subscription_login_tests.rs`.
- **Enrollment.** `scripts/opencode-enroll.py` runs `opencode auth login -p openai -m "ChatGPT Pro/Plus (headless)"` in a fresh 0700 HOME and XDG tree. It validates the single `openai` OAuth entry and writes it to a new 0600 file for the C5b upload. It prints only the sha256 and the expiry. Tests are in `scripts/tests/test_opencode_enroll.py`.
- **Template pin.** `packaging/sandbox/pins.json` adds `opencode-linux-x64@1.18.35`. The packager, `Dockerfile.runtime`, the bundle manifest, the credential scan, the `runtime_bundle.rs` test and C3b public constants are updated.
- **Live test.** `crates/aq-worker/tests/opencode_live.rs`, described below.

### Live test (`crates/aq-worker/tests/opencode_live.rs`)

- The recipe and private home come from `OpenCodeAgentHome::install` under `confinement::authorize(Container)`, relocated to `/aq/work/oc-home`. The runner script carries the recipe's env as an `env -i` array and its `opencode.json` as a quoted heredoc. It carries no credential.
- The controller lifecycle is the same as I4a: `open` → `register` → `reserve` (harness `opencode`, CLI `1.18.35`, template digest) → `accept_with` → `launch` → `runner_exit` → `read_file` → `stop` → `destroy` → `list_owned` empty. Teardown runs before any outcome assertion.
- The runner:
  1. wipes the dummy lease material;
  2. creates a bare publish repo and a crate whose `add` returns `a - b`, and confirms `cargo test` fails (RED);
  3. runs `opencode run` to fix the crate;
  4. exports the session;
  5. runs `cargo test` (the check), commits and pushes (the publish);
  6. checks that no `auth.json` exists;
  7. removes the private home.
- Reaching Ollama. The container sees the host at pasta's `169.254.1.2`, which pasta maps to the host's eth0 address. Ollama binds only `127.0.0.1`, so the test runs a relay on the host eth0 address (`AQ_OPENCODE_LIVE_RELAY_BIND`) that:
  - accepts only peers equal to that address (pasta's presentation of the sandbox);
  - rewrites `Host` to the loopback upstream and forces `Connection: close`.

  The rewrite is needed because Ollama's DNS-rebinding guard answers 403 to a non-local `Host`, which is what the first attempt hit.
- Readers. The exported session runs through both `aq_observation::Normalizer` and the `aq_observation_engine` path (`Context` plus `normalize` over an in-memory `Rows`). The two must agree on usage events, tool starts and results, roles, turns and providers.
- Pure tests: `docker_local_offers_container_confinement_only` and `runner_uses_the_installed_recipe_and_carries_no_credential`.
