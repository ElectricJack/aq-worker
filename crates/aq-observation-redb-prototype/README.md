# Isolated redb delivery prototype

This unpublished0.0.1 experiment tests a row-based alternative to the separately qualified `aq-observation0.1.0` JSON spool. The reference source, wire packages and runtime are unchanged. There is no migration, production worker adapter, authority admission, central transport authentication, raw artifact transfer, parser-state integration or new command.

The exact dependency is redb4.4.0 (MIT OR Apache-2.0), an embedded Rust library requiring no external service. Source/seen/outbox/event-ID/delivery rows use one private database and exclusive owner. Every write uses `Durability::Immediate` and two-phase commit; quick-repair is a measured option, not silently enabled. The backend admits a private canonical directory and no-follow regular same-owner0600 single-link file; positional writes/resizes cannot exceed the configured physical cap. A bounded page cache is configured. Locking is exclusive whole-file; no experimental multi-process feature is enabled.

Candidate settings are64 MiB physical,16 MiB logical retained values/selected key bytes,4 MiB cache,16 sources,65,536 known identities,256 ordinary facts/2 MiB plus16 reserved gaps/64 KiB,32 facts/256 KiB per packet,128 changed Seen rows per append. Logical quota is not total physical disk use. Event-ID digests remain retained and counted; there is no automatic history eviction. Btree overhead/COW headroom can cause conservative refusal before the logical bound. The physical-cap test proves a growth failure leaves an unchanged committed projection; it does not prove gap/ACK admission under every physical-disk failure. Full reserve sizing, long reader effects and compaction remain acceptance gates.

`append` is an already-normalized, bounded prototype adapter input. It atomically checks expected cursor, exact source/binding/parser and global sequence; updates known identities; inserts immutable outbox facts and event-ID digests; and advances cursor/counters. It does not implement the full Normalizer transaction view/delta or verify worker-authored accounting claims. Prepare reads only a bounded outbox prefix. Begin-send updates only durable retry metadata. ACK validates an exact CON03 Receipt against retained packet bytes, deletes only that prefix and updates counters/receipt atomically. Duplicate current receipts are idempotent; retry exhaustion retains the intent for a late exact receipt. No network effect occurs inside a transaction.

Startup audits the complete bounded projection, so startup remains O(retained rows). Small delivery operations never call that audit or scan Seen history. Any mutation error poisons that instance conservatively; reopening revalidates before another send can be prepared. Existing files shorter than the pinned redb4.4.0 512-byte super-header are rejected before the create-or-open backend engine entry point; empty/truncated bytes remain unchanged. The stable backend API has no separate open-only variant. Missing/corrupt metadata is never initialized implicitly. Unknown directory members are retained/refused. This is not the production authenticated initial transport admission API.

Tests compare exact generated Packet, retry and Receipt behavior with the qualified reference spool and fake CON03 peer; reject scope/payload/receipt/quota errors; verify unknown-restart/late ACK; enforce private ownership and actual physical transaction cap; and cut every observed write/resize/sync boundary before and after each append/prepare/send/ACK. Deterministic IO errors and actual child process exits reopen to an entirely old or new projection, including cursor/facts/known rows/pending packet/ACK. This is process-exit and IO-fault evidence, not hardware power-loss certification or exhaustive corrupt-page verification.

```sh
cargo test -p aq-observation-redb-prototype --offline -- --nocapture
cargo clippy -p aq-observation-redb-prototype --all-targets --offline -- -D warnings
cargo fmt --package aq-observation-redb-prototype --check
cargo run --release -p aq-observation-redb-prototype --example measure --offline
cargo run --release -p aq-observation-redb-prototype --example reference_measure --offline
```

The measurement examples use synthetic retained identity history and real normalizer-generated single-event batches. They exclude population time and never contact providers/coordinators. There are35 measured repetitions at small and approximately12 MiB logical history, with quick-repair on/off for redb. Backend metrics report bytes/syncs/file growth; reference metrics report output journal lengths, not syscall-traced bytes. This experiment does not refactor active-normalizer cloning or qualify end-to-end source collection. No production storage replacement, migration or performance guarantee follows from it.
