# aq-observation0.1.0 candidate

Independent Rust normalization and durable observation storage over exactly `aq-lifecycle-protocol =0.1.0`. This crate contains no provider calls, pricing engine, task settlement, grant/launch authority, notification sender or production coordinator. Existing session/lifecycle packages are unchanged.

The [pinned format inventory](artifacts/source-formats.json) distinguishes primary source-code format evidence from released CLI qualification. Codex67f0994 uses native cumulative totals; repeated totals do not charge last-token usage again. Claude9a9b8e8 uses v1-reference-backed JSONL message IDs, with released product qualification pending. Gemini6814e00 handles JSONL metadata/full-message updates/set/patch/rewind; unsupported mutations emit gaps. OpenCode6c24ec9 accepts individual public Session.Message DTOs on an explicitly scoped native-session channel; a full export-envelope/API collection adapter is pending. Synthetic source fixtures and generated normalized goldens do not certify a selected installed CLI. Advertisements keep `selected_released_cli_qualified` and `complete_accounting_policy_eligible` false.

Native absent fields stay unknown, distinct from reported zero. Counts retain their native overlap semantics; input/cache/reasoning categories must not be summed blindly. Costs without verified receipt/rate-card basis stay unknown. Mixed-model cumulative attribution and lost parser context are unavailable rather than inherited from the launch model. A native message ID is not automatically a provider API call ID: central AQ22 owns cross-source precedence, original-task lineage mapping, append-only accounting and corrected aggregates. Worker lineage/account/model/category-policy/cost labels remain claims.

`Normalizer` uses immutable source/binding identity, exact parser artifact digest, native record/call identities and known-prior correction references. Repeated native chunks/history cannot create another usage fact; imported unknown history remains incomplete. Conversation rewind changes display state and never undoes incurred usage. Retained Gemini state contains only counts, IDs and logical content digests, not prompt/tool text. Logical text/tool references are unuploaded claims, not retention receipts or retrieval permission. Redaction does not promise that arbitrary native identifiers contain no sensitive data.

`Discovery` requires an admitted native root and known key. Exact paths never fall back to another session; bounded Codex/Gemini scans refuse ambiguity/budget exhaustion. Gemini short filenames require full metadata-key confirmation. Obtaining the native key from the launched harness remains a host-adapter responsibility. `SourceFile` pins canonical root, exact basename/device/inode and rejects symlink/hardlink/ownership changes. Reads are at most256 KiB, records64 KiB, polls32 records. Partial suffixes remain unconsumed. A bounded64-byte consumed-prefix anchor detects near-cursor rewrites; this is not a cryptographic proof that all historical file bytes stayed unchanged.

`Spool` atomically commits cursor, normalizer state and outgoing facts in one private checksummed journal. Ordinary events cannot consume reserved gap capacity. Default overflow holds the cursor; explicit GapAndHold records the affected interval then fences further collection pending reconciliation. Missing/rotated/truncated sources emit durable gaps. Bounds can hold progress; they never imply complete accounting or permission to delete raw evidence. Fixed-name orphan temporaries refuse reopening for explicit recovery, preserving uncertainty. The retained-temp test exits a child process after temporary-file fsync and before rename: the committed journal remains unchanged, pending.tmp survives, and reopen refuses while preserving both files. The separate BeforeRename injection cleans its known uncommitted file and tests an IO-error path. Neither certifies machine/power-loss behavior. Automatic orphan selection/deletion is deliberately absent; explicit owner recovery is required.

Node-wide sequence survives admitted boot transitions in the same retained spool. Creation requires an explicit initial central transport-owner admission; missing/corrupt open never reseeds. An admitted boot change preserves committed old facts/frozen packets, emits source-fence gaps and excludes old-boot live file/DTO collection. Only verified immutable retained replay may process an old source further. Packets use contiguous same-boot prefixes while the per-node sequence spans all sources/boots. There is no fresh-floor recovery API: lost transport ownership requires central source-gap/recovery admission and retirement of old ownership.

Packets are exactly CON03 Packet/Batch and Receipt. Packet identity/bytes are frozen durably before send; unknown acknowledgment replays the same packet. Retry count/time/backoff are bounded and exhaustion retains intent. Exact receipts prune only the recorded prefix. Coordinator receipt authentication and historical boot/source ownership checks are required from the eventual host transport adapter; a worker-authored receipt is not proof. This module holds no network exchange or worker authority lock. Actual renewal/cancellation scheduling must run independently of this blocking filesystem component; no runtime control latency guarantee is claimed here.

Explicit parser reconciliation requires a ReparsePlan with exact source/generation/binding/old-new parser, immutable operation ID, selected known-prior EventRefs and transcript retention receipt. VerifiedReplay checks actual SHA/length/TTL/record bounds and a host ReplayAuthority callback; no permissive production verifier is provided. Replay cursor and corrections commit together. Only selected known facts can correct prior normalization; unknown historical observations emit gaps. Live collection is excluded, the retained live cursor is preserved and finish requires every selected fact handled. Raw bytes are ephemeral input, never copied into the journal. The retention owner/authentication adapter and raw artifact transfer remain separate required integrations.

This is the staged pure component; worker journal/transport integration remains a root review gate, and actual four-harness qualification belongs to INT03.

The release measurement example (`cargo run --release -p aq-observation --example measure --offline`) uses valid synthetic retained-journal snapshots, not native transcripts or a fill-throughput benchmark. The small snapshot is11,228 bytes (one source,4 retained identities,4 queued events); the large snapshot is12,740,029 bytes of a16 MiB cap (8 sources,640 identities each,32 raw-record digests per identity,192 queued events). Local warm-filesystem before/after measurements reduced large-snapshot median idle polling from16.49 ms to0.020 ms, partial polling from13.38 ms to0.020 ms, and one32-record burst from680 ms to240 ms. Collection clones only the active source while evaluating records, computes retained lane cost once, and clones the global state only for a nonempty committed batch. Normalization still clones the active source per record, and journal commits still serialize/hash/rewrite all retained metadata: observed large-snapshot prepare/send/ACK were231/134/128 ms after the change. These are illustrative single-host samples, not percentile guarantees or scalable-delivery qualification. The eventual runtime must isolate blocking persistence from authority renewal/stop scheduling and measure that boundary; segmented/checkpointed storage may be required at higher retained-history budgets.
